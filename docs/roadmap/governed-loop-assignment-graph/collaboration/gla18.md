# GLA18: Reviewed direct-message trigger and explicit acknowledgment

One installed provider-neutral adapter accepts only bounded, content-addressed reviewed-input message observations. Its exact plan binds adapter version and hash, source event and assignment-scoped idempotency key, current workstream, assignment revision, source lease, exact recipient, artifact, and the existing mention plan.

Apply re-inspects and delegates to the workforce handoff transition. Exact source replay within the assignment returns current; conflicting reuse records nothing.

The exact active recipient-agent coordinate can separately record acknowledgment of the handoff. Assignment state and `assignment.handoff.acknowledged` commit together. Communication contract v2 upgrades only acknowledgment; delivery and action remain separate.

The local command does not authenticate a human principal. The file adapter claims no live platform authentication, provider start, implicit assignment creation, or unattended execution.

## Acceptance

Acceptance requires:

- Pure trigger-plan, idempotency, conflict, recipient authority, event rollback, privacy allowlist, and projection tests.
- CLI plan/apply and acknowledgment coverage.
- Additive product-host protocol v4 discovery.
- A packed public-CLI trigger-to-handoff-to-acknowledgment journey with delivery still unobserved.
