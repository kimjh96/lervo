# GLA10: Bounded local improvement observation adapter

A production local adapter adds no measurement authority to the stock CLI. An authorized host may collect a request from local canonical events, but exact register and observe apply still re-inspect the narrower verification port and reproduce reviewed evidence.

The first metric, repository-wide `verification_success`, divides passed canonical verification completions by every valid completion in an inclusive window. Unsupported, empty, and over-capacity measurements remain explicitly unavailable.

Event scanning, pure metric projection, receipt binding, project-storage lifetime, shared conformance, CLI injection, and CAS protocol persistence remain separate responsibilities.

## Acceptance

Focused tests must cover:

- Shared adapter conformance, exact counts, and boundary inclusion.
- Rejection of count, phase, pattern, window, and backdated-evidence drift.
- Duplicate-evidence failure; unsupported and empty abstention.
- Scan and evidence capacity limits; safe storage close.
- Default no-authority behavior.
- A full baseline-to-promotion-to-treatment CLI host-injection dogfood journey.

Quality, type, package-boundary, build, full tests, documentation and knowledge lifecycle, foundation checks, and task-base release completion must pass with reviewed minor release intent.
