# Managed-context canaries

## Initial design and preparation: v1–v5

24. [ADR-0277](../../../decisions/search/activation/provider-shadow-structured/0277-stage-managed-context-relational-canary.md) established a default-off, managed-run-only canary with provider-neutral selection, exact E1–E4 evidence separation, fail-closed delivery, and a later isolated read-only ceiling of 16 runs and 32 calls. Implementation and provider-free verification were permitted; live execution and context effects required a separate exact prepared checkpoint over an eligible registered corpus.
25. [Managed canary v1](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v1.md) stopped after its first Codex selection call emitted a forbidden command signal. It produced no task sample and remains terminal. [ADR-0280](../../../decisions/search/activation/provider-shadow-structured/0280-add-an-opt-in-codex-responses-no-tool-transport.md) added an optional no-tool Responses transport; [ADR-0281](../../../decisions/search/activation/provider-shadow-structured/0281-prepare-managed-context-canary-v2.md) retained it in an unexecuted 32-call checkpoint. [ADR-0282](../../../decisions/search/activation/provider-shadow-structured/0282-remove-api-key-requirement-from-managed-context-canary.md) rejected a separate API key as a normal product prerequisite and prepared API-key-free, task-only v3. V3 froze exact passed V18 provider-specific selections, locally revalidated their current projection, reused native provider sign-in for 16 ordinary task calls, and made zero selection calls. Preparation and the decision authorized no live traffic.
26. [V3 provider-free preparation](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v3.md) passed every exact evidence binding with zero calls, but retained zero added sources across eight Codex runs and one added source across eight Claude runs. It was rejected before execution because it could not measure comparable linked-context effects. [ADR-0283](../../../decisions/search/activation/provider-shadow-structured/0283-prepare-deterministic-linked-context-canary-v4.md) prepared provider-neutral v4, selecting every bounded current linked candidate in deterministic order. V4 retained native provider sign-in, zero selection calls, and a 16-task-call ceiling, and required nonempty exact added context in every run.
27. V4 provider-free preparation proved 16/16 nonempty exact selections, with two to six candidates per run, zero provider calls, and a 16-task-call ceiling. Deterministic runtime implementation followed that snapshot, so [ADR-0284](../../../decisions/search/activation/provider-shadow-structured/0284-prepare-exact-deterministic-native-session-canary-v5.md) required a fresh v5 manifest bound to the implemented schema-v2 runtime and built CLI. V5 created no selection adapter, required no user API key, and preserved native signed-in Codex and Claude task sessions. Preparation authorized no live traffic or activation.
28. V5 prepared 16/16 nonempty exact selections and manifest `sha256:85a22b76aa5a07ab58e66eb58035cedbd64b83780b8c356b6cc835f1c90d8f02` with zero calls. Exact authorization and attempt-before-call execution followed that snapshot, so [ADR-0285](../../../decisions/search/activation/provider-shadow-structured/0285-authorize-exact-key-free-managed-canary-v6.md) preserved v5 and required a fresh v6 source/build binding before native-session execution.

## Execution boundaries and prompt constraint: v6–v12

29. V6–v10 each stopped at the first newly exposed technical boundary without retry, correcting exact authorization, read-only role behavior, runtime clock binding, past manifest coordinates, and linked-selection forwarding while preserving immutable failure evidence. V10 completed one Codex model turn but rejected its completion because deterministic linked selections were omitted before E1. [ADR-0290](../../../decisions/search/activation/provider-shadow-structured/0290-forward-linked-selections-for-key-free-managed-canary-v11.md) fixed only that forwarding boundary and prepared fresh v11.
30. [Managed canary v11](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v11.md) completed eight Codex and eight Claude native-session runs with zero technical failures, selection calls, retries, API keys, or repository mutations. Both providers retained 100% recall. Codex passed at 81.25% mean precision; Claude reached 50.14%, with three runs below 50%. Deterministic selection eliminated all 16 selection calls and halved the two-stage provider-call ceiling; activation remained blocked.
31. [ADR-0291](../../../decisions/search/activation/provider-shadow-structured/0291-constrain-provider-neutral-e4-references-for-managed-canary-v12.md) authorized a provider-neutral prompt-only E4 constraint and one fresh paired confirmation. [Managed canary v12](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v12.md) completed 16/16 runs without technical failure. Claude precision improved to 65.97% but retained two per-run failures. Codex precision improved to 91.67%, but two recall failures reduced mean recall to 87.5%. [ADR-0292](../../../decisions/search/activation/provider-shadow-structured/0292-reject-prompt-only-e4-constraint-after-managed-canary-v12.md) rejected and rolled back the instruction. A successor required a typed task-evidence versus governance-context boundary; activation remained default-off.

## Typed context and claim eligibility: v13–v14

32. [ADR-0293](../../../decisions/search/activation/provider-shadow-structured/0293-type-task-evidence-and-governance-context.md) added required `task_evidence` and `governance_context` roles from context planning through E3 receipts. Codex and Claude received identical role metadata. Governance documents received no E4 token; task evidence retained exact tokens. Common tests preserved raw unfiltered E4 observation and rejected role substitution. No provider call or activation was authorized.
33. [ADR-0294](../../../decisions/search/activation/provider-shadow-structured/0294-prepare-typed-context-managed-canary-v13.md) fixed a provider-free v13 checkpoint over the exact v12 cases, repetitions, ordering, and accuracy gates. It bound typed-boundary source bytes, v12 terminal evidence, repository snapshot, built CLI, rollback predecessor, and an eight-Codex plus eight-Claude native-session ceiling. The v13 entrypoint exposed preparation and status only; zero calls and no activation were authorized.
34. [ADR-0295](../../../decisions/search/activation/provider-shadow-structured/typed-context/0295-authorize-typed-context-managed-canary-v14.md) translated the user's explicit execution direction into a fresh source-current v14 checkpoint because v13 remained immutable and preparation-only. V14 bound exact authorization and fail-first execution sources, persisted attempts before calls, and revalidated source and build before every sequential task. It preserved the eight-Codex plus eight-Claude ceiling with zero selection calls, API keys, retries, or activation.
35. [Managed canary v14](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v14.md) completed all 16 native-session runs with zero technical failure, selection calls, retries, API keys, writes, or repository mutations. Both providers achieved 100% recall. Codex passed at 87.5% mean precision; Claude reached 60.07%, with two runs below 50%. Mean duration improved 7.61% for Codex and 12.95% for Claude relative to v12; deterministic selection retained the 50% provider-call reduction. [ADR-0296](../../../decisions/search/activation/provider-shadow-structured/typed-context/0296-reject-activation-after-typed-context-managed-canary-v14.md) rejected activation and required a task-evidence eligibility diagnosis before another call.
36. [ADR-0297](../../../decisions/search/activation/provider-shadow-structured/typed-context/0297-separate-claim-reference-eligibility-from-task-evidence.md) separated direct claim authority from linked supporting context. Linked-only evidence remained E1-selected, E2-loaded, and E3-injected but received no E4 token. Direct task provenance remained eligible and took precedence when both occurred.

## Measurement, capacity, and activation: v15–v18

37. V15 stopped after one Codex task call when measurement read a missing bounded outcome field. [ADR-0298](../../../decisions/search/activation/provider-shadow-structured/typed-context/0298-stop-v15-on-measurement-projection-failure.md) preserved the failure and derived sorted unique reference IDs from canonical E4 into the bounded summary.
38. V16 stopped after 11 accepted observations when a twelfth completed task call reached the 64-record canary limit. [ADR-0299](../../../decisions/search/activation/provider-shadow-structured/typed-context/0299-stop-v16-and-expand-canary-observation-capacity.md) preserved the terminal population and raised the bounded owner-only record cap to 128 without deleting history.
39. V17 stopped after 10 accepted observations when the next pre-provider preparation found 4,105 relevant execution events, exceeding the 4,096 cap. [ADR-0300](../../../decisions/search/activation/provider-shadow-structured/typed-context/0300-stop-v17-and-expand-complete-event-capacity.md) preserved the terminal population and raised the complete-event cap to 8,192, retaining the 16 MiB cap and full privacy validation.
40. [Managed canary v18](../../../evidence/search/provider-shadow/linked-evidence-managed-canary-v18.md) completed all 16 fresh runs with zero technical failures, selection calls, retries, API keys, or repository mutations. Both providers achieved 100% recall. Codex achieved 83.33% mean precision and Claude 79.17%, with no per-run failure. [ADR-0301](../../../decisions/search/activation/provider-shadow-structured/typed-context/0301-activate-deterministic-claim-eligible-linked-context.md) activated the zero-selection-call deterministic path for ordinary managed runs and kept the exact canary separately authorized.

## Retirement of ordinary linked selection

41. The [paired lexical-only comparison](../../../evidence/search/paired-uplift/lexical-linked-uplift-v1.md) completed 32 Codex and Claude runs. Linked context reduced equal-provider claim recall and complete-answer rate by 6.25 percentage points each. [ADR-0302](../../../decisions/search/activation/provider-shadow-structured/typed-context/0302-retire-linked-default-and-use-search-engine-ports.md) retired ordinary linked selection, preserved the exact canary as default-off history, and routed future retrieval improvement through existing search-engine ports.
