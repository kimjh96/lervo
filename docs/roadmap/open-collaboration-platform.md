# Open collaboration platform

Status: `proposed`
As of: 2026-10-04

## Outcome

Make Lervo the operating experience defined in [ADR-0452](../decisions/foundation/0452-open-collaboration-by-default-with-authority-at-consequential-effects.md): an owner-run organization of durable agents that converse and self-organize, keep working and improving, act for the owner within a mandate, follow work between the Mac terminal and Discord, and ground and measure every turn, on a hardened provider-neutral local-first core. The [strengths matrix](open-collaboration-platform/strengths-matrix.md) records what each reference product does well, what Lervo does better, and the verified status of every adoption.

Lervo is `converged` only when the six true-Lervo journeys (ADR-0452 section 6) pass on installed Nodes with real Codex and Claude and a real guild, each with a regression test at the boundary. Until then every entry below carries the ADR-0452 completion label that its evidence supports.

## Slice 0 delivery notes

### Platform boundary ratchet (`wired`)

`pnpm architecture:check` runs `scripts/quality/check-platform-boundary.mjs` after the package-boundary check, and the code-quality workflow runs it on every pull request and `main` push. The scan covers non-test sources under `apps/*/src` and `packages/*/src`. For Discord it excludes `packages/adapter-discord`, `packages/discord-gateway`, and `discord-*` files. For Slack it excludes `packages/adapter-slack` and `slack-*` files. `scripts/quality/platform-boundary-baseline.json` keeps one section per platform, recording each file's matching line count and, for `conversation-*` and `supervision-*` files, the adapter modules they import. The first baseline recorded 325 Discord lines in 50 files and 18 Slack lines in 4 files. The check fails when a count grows, when a file outside the baseline mentions a platform, or when a guarded file adds an adapter import. `pnpm architecture:baseline` only lowers counts and refuses to run while a leak exists. `scripts/quality/test/platform-boundary.test.mjs` injects leaks into a fixture tree, checks the downward-only refresh, and keeps the tracked baseline current. The label stays `wired` until a CI run on the hosted workflow has failed on a real leak.

### Shared retry policy and error-fidelity lint (`wired`)

`RetryPolicy` in `@lervo/execution-contract` has three fields. `maximumAttempts` (1 to 100) is the counter ceiling. `attentionAfter` (1 to `maximumAttempts`) is the attempt after which automatic retry stops. `backoff` holds `initialDelayMs`, `multiplier` (1 to 10), and `maximumDelayMs`, each bounded to one day. `admitRetryAttempt` refuses any counted attempt above `attentionAfter`. `decideRetryAfterFailure` either schedules a capped exponential delay or returns `attention_required` with one of three reasons: `attempts_exhausted`, `attempt_ceiling_exceeded` (the counter is above `maximumAttempts`, which is a contract violation), or `non_retryable_failure`. An invalid policy or counter fails with `invalid_retry_policy` before any attempt runs.

The conversation outbound delivery cycle in `@lervo/interaction` now expresses ADR-0424's existing bound, a fixed delay with three attempts by default, through this contract, so healthy paths behave as before. It also admits each claimed lease before calling the adapter. A lease whose counter already exceeds `attentionAfter` because earlier attempts were interrupted moves straight to `attention_required`, with failure code `delivery_attempts_exhausted` or `delivery_attempt_ceiling_exceeded`, and the adapter is not called again. That is the loop that let one Tarin outbound reach 20,589 attempts. Every cycle result now carries `attention[]`, one `ConversationDeliveryAttention` per outbound that left automatic delivery in that cycle. Its required fields are `outboundId`, `integrationId`, `failureCode`, `reason`, `attemptCount`, `attentionAfter`, `owner` (`conversation_integration_operator`), and `recoveryCondition` (`verified_receipt_reconciliation`, the ADR-0424 path). The record holds identifiers and bounded codes only, never message content, provider text, or credentials. It records no new canonical event. Because `attention_required` rows are never claimed again, each outbound appears in at most one cycle's `attention[]`. If the store refuses the transition, the cycle throws and the lease expires. The next claim then exceeds the bound and is refused again without delivery. The regression in `packages/interaction-sqlite/test/native-chat-runtime.test.ts` replays three interrupted claims and then 20 more cycles, and confirms the adapter is never called and the stored counter stays at 4. Publishing a notice from `attention[]` to an operator surface, and applying the contract to replica cycles, knowledge jobs, and supervision dispatch, remain open.

ESLint rule `lervo/require-caught-error-cause` (`scripts/quality/lib/eslint-error-cause-rule.mjs`) applies to `apps/*/src` and `packages/*/src`. It fails when code inside a catch clause throws a newly constructed `*Error` without passing the caught error, either as `cause` or directly. It also fails when the catch clause discards its parameter. `scripts/quality/test/eslint-error-cause-rule.test.mjs` covers the valid and invalid forms. The 155 findings that already existed when the rule was enabled are recorded per file in ESLint's bulk-suppression file, `eslint-suppressions.json`. That file is ESLint-owned, so Prettier skips it. New findings fail `pnpm lint`. A stale suppression also fails until `eslint . --prune-suppressions` removes it, so the baseline can only shrink. Adding entries with `--suppress-rule` requires a reviewed change that names the reason. `code`, `stage`, and the redacted `causeDigest` on wrapped failures remain open.

## Acceptance metrics

Reported weekly from ADR-0459 projections, per channel and agent:

- Hit precision at or above 0.7 on conversation and supervision channels; miss rate below 0.1; stale-hit rate below 0.02.
- Tokens per successful outcome trending down over four weeks for one standing goal; no supervised run exceeds its reservation in flight.
- Duplicate human-turn answers below 5 percent; exchange budget exhaustion visible every time it occurs.
- Per-change knowledge jobs reaching `current` at or above 90 percent; zero generated review sources.
- Replica failures: at most one attention item per divergence identity; zero silent repeats.
- Proxy settlements: 100 percent inside mandate scope, each with a recorded decision event.
- Deliberation: Tier 0 rate of 100 percent on `adr_authoring` points; `outcomeChangeRate` above zero for Tier 1 and 2; zero `unverified` artifacts counted toward convergence; `laterDefectRate` reported with and without deliberation; Tier 0 cost at or below 24,000 tokens per run.
- Document freshness: time to a verified candidate p90 under 30 minutes for `safety` and `entrypoint` findings; false-positive rate below 10 percent; acceptance rate above 70 percent; tokens per applied update at or below 40,000; revert rate below 5 percent; no stale entrypoint older than one escalation batch window without an open candidate or owner question.

## Corrections to the diagnosis

Verification changed several premises: "Tarin" is a deployment identity, not a code mapping; `waiting_decision` tracks the supervisor's own effects, not user decisions; `.gitignore` already excludes the convergence grant, and the real gap is the missing explicit pathspec exclusion; mentions of several agents already produce several owners; the hire path already admits allowlisted agents and supervision already detects staffing gaps; the conversation `not_applicable` rule is surface-neutral; the built-in integrations file is an open extension point; the package-boundary script reads dependencies, not imports; two patterns were promoted, not one; and the supervision token ceiling is already installed-proven, so the research claim that Lervo lacks a token-budget experience is outdated. Deliberation audit: all 11 formal runs happened on 2026-08-25 from the CLI inline policy with 0 `converged`, no `deliberation`-scope usage, and no downstream consumer; the Discord natural path never reached the deliberation core because a separate discussion protocol was wired for the same effect; the 2026-10-01 "Sol and Opus opinions" reply was ordinary conversation with only Claude usage observed.
