# Lervo v0 Roadmap

Status: `complete`
As of: 2026-08-24

## Goal

Deliver a local-first, provider-neutral workflow in which a repository can initialize, compile knowledge, run Codex or Claude under explicit policy, verify changes, retain evidence, and optionally coordinate through a Hub.

## Current repository-knowledge hardening

Completed on 2026-08-23:

- repository-wide bounded discovery including typed sensitive logs and provider surfaces;
- explicit publication language with English as the v1 default;
- bounded, sharded navigation and safe stale-output deletion;
- minimum-only initialization and lazy feature directories;
- missing README and AGENTS lifecycle during migration;
- provider bridge separation for CLAUDE;
- repository-wide non-English surface audit with privacy-bounded file and line coordinates;
- enforced size bounds for root entrypoints and maintained documentation;
- short current vision, architecture, execution, and roadmap contracts under `docs/`;
- complete test, build, release artifact, SBOM, attestation, distribution, packed CLI, documentation, and brand checks;
- complete English migration across runtime, fixtures, documentation, and historical ADRs, with every measured language-audit category at zero;
- Lervo self-migration with lint and zero-change replan.
- bounded semantic decision directories, `docs/knowledge` publication, and two-hex machine-registry sharding applied through the migration command with rollback and compatibility coverage.
- repository-scoped decision taxonomy with explicit routes, fail-closed classification, and shared migration/lint leaf enforcement; `foundation` is no longer a fallback.
- lineage-bound taxonomy refinement applied to the Lervo repository: the former broad operations leaf was split into trace, diagnostics, security, services, and storage routes, with durable recovery coverage for pruned shard parents.
- external-repository pilot preflight hardened initialization so fresh repositories receive a product-neutral starter taxonomy instead of Lervo's own product domains.
- the Shiflo pilot hardened legacy generation adoption, token-boundary lexical query behavior, and managed snapshots for real mobile repositories with large generated native build trees.
- the Shiflo pilot completed the full local `init -> migrate -> lint -> query -> managed Codex/Claude run -> verification` path, including an observed Claude content failure that project verification rejected and successful isolated result-publication evaluation for both providers.
- repository-wide semantic document routing now moves classifiable documents from legacy `docs/`, root, and nested locations instead of merely registering them; unclassified or tied documents block completion.
- Claude rules and skills normalize into provider-neutral instruction routes and `.agents/skills`, with brace-aware path conditions, exact reference repair, an AGENTS routing block, and a bounded CLAUDE import bridge.
- destination-bound Node reconciliation closes the production-only gap where a registered Hub received no local managed-run events; long histories now backfill in bounded contiguous cycles without coupling CLI producers to Hub configuration.

See [ADR-0189](../decisions/knowledge/repository/0189-typed-repository-agent-surface-inventory.md), [ADR-0190](../decisions/knowledge/repository/0190-language-aware-bounded-repository-publication.md), [ADR-0191](../decisions/knowledge/repository/0191-bounded-hierarchical-repository-layout.md), [ADR-0192](../decisions/knowledge/repository/0192-repository-scoped-decision-taxonomy.md), and [ADR-0193](../decisions/knowledge/repository/0193-semantic-repository-and-agent-surface-migration.md).

## Remaining v0 product work

No implementation item remains in the agreed v0 scope. The semantic repository and agent-surface correction passed the full repository suite, all 71 package builds, release and distribution checks, documentation lifecycle checks, strict English audit, Lervo self-migration with a zero-change replan, the external [Shiflo acceptance pilot](../evidence/pilots/shiflo-v0.md), and the [WSL Hub and Shiflo release acceptance](../evidence/pilots/wsl-hub-shiflo-release-acceptance.md). The root and package READMEs document source-checkout installation without npm publication. Release or product expansion requires a separate decision.

The language audit remains the measurement source of truth and the strict language check is now an effective release gate. The 2026-08-23 completion audit reports zero files and zero lines in runtime, test-fixture, and documentation categories. The English npm description, release manifest, and SBOM were regenerated and locally verified together; no package publication occurred.

These items are repository work, not requests for a new hosted semantic product.

## Explicitly separate future scope

- Gemini and Copilot provider bridges.
- Fuzzy semantic merge or automatic fact promotion.
- External graph databases, embeddings, or Hub semantic services.
- Production credentials, external publishing approvals, and organization deployment policy.
- Automatic upgrade and multi-instance service orchestration.

Future scope requires measured need and a separate ADR; it is not silently inherited from v0.

## Acceptance gates

- Local `init -> migrate knowledge -> apply -> lint -> query -> managed run -> verification` succeeds without a Hub.
- Existing user documents remain byte-safe unless exact approval authorizes a change.
- Codex and Claude pass their shared contracts.
- A clean clone or another Lervo installation reproduces tracked knowledge.
- Generated documents remain English, bounded, and idempotent.
- No dormant documentation or feature directory is created.
- Documentation lifecycle, typecheck, targeted tests, build, and applicable distribution checks pass.
