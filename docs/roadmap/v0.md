# Lervo v0 roadmap

Status: `complete`
As of: 2026-08-24

## Goal

Deliver a local-first, provider-neutral workflow that initializes repositories, compiles knowledge, runs Codex or Claude under explicit policy, verifies changes, retains evidence, and optionally coordinates through a Hub.

## Separate future scope

- [Repository onboarding and agent workforce](onboarding/agent-workforce.md): one coherent initialization lifecycle, durable repository-scoped agents, executable specialist roles, natural-language assignment, evidence-bound handoff, and automatic safe finalization.
- [Public README migration](knowledge/public-readme-migration.md): preserve public entrypoints by default and separate optional audience-aware improvement from repository readiness.
- [Repository Node fleet and automatic Hub replication](coordination/repository-node-fleet.md): make the implemented replication contract operationally automatic for every Hub-enabled repository, support multiple repositories per device, and repair installed runtime failures without user bookkeeping.
- Gemini and Copilot bridges.
- Fuzzy semantic merge or automatic fact promotion.
- External graph databases, embeddings, or Hub semantic services.
- Production credentials, external publishing approvals, and organization deployment policy.
- Organization-wide fleet policy and unattended cross-version rollout beyond repository-scoped automatic runtime reconciliation.

Future scope requires measured need and a separate ADR; v0 does not inherit it.

## Operational gap discovered after completion

The workstream replication contract and in-process installed-runtime acceptance tests are complete, but the live Mac installation inspected on 2026-08-25 did not satisfy the product-level automatic-replication outcome. Its single global Node service targeted Shiflo, was crash-looping, and the current runtime reported `local_batch_invalid`; Roven had no independent Node deployment. This does not invalidate the protocol implementation, but it blocks a claim that newly initialized repositories are automatically replicated in the installed environment. Remediation and installed acceptance criteria are tracked in [Repository Node fleet and automatic Hub replication](coordination/repository-node-fleet.md).

## Acceptance gates

- Local `init -> migrate knowledge -> apply -> lint -> query -> managed run -> verification` succeeds without a Hub.
- User documents remain byte-safe without exact approval.
- Normalization preserves section coverage, managed blocks, code and link coordinates, skill identity, and skill-resource lifecycle; Shiflo is not merely relocated legacy content.
- Codex and Claude pass shared contracts.
- A clean clone or another installation reproduces tracked knowledge.
- Direct Codex and Claude prompts invoke the hook or fail closed; installation reports the provider-native trust action, readiness remains incomplete until invocation evidence exists, and sessions remain unmanaged.
- Generated documents are English, bounded, and idempotent.
- No dormant documentation or feature directory is created.
- Documentation lifecycle, typecheck, targeted tests, build, and applicable distribution checks pass.
