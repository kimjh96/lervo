# Lervo v0 roadmap

Status: `complete`  
As of: 2026-08-24

## Goal

Deliver a local-first, provider-neutral workflow in which a repository can initialize, compile knowledge, run Codex or Claude under explicit policy, verify changes, retain evidence, and optionally coordinate through a Hub.

## Repository-knowledge hardening

Completed on 2026-08-23:

- bounded repository discovery, including typed sensitive logs and provider surfaces;
- English-default publication, language auditing, and an effective strict-language release gate;
- bounded sharded navigation, safe stale-output deletion, minimum initialization, and lazy feature directories;
- migration support for missing README and AGENTS files, plus a separate CLAUDE provider bridge;
- bounded root entrypoints and maintained documentation;
- current vision, architecture, execution, and roadmap contracts under `docs/`;
- complete test, build, release artifact, SBOM, attestation, distribution, packed CLI, documentation, and brand checks;
- English migration across runtime, fixtures, documentation, and historical ADRs, with all measured audit categories at zero;
- Lervo self-migration, lint, and zero-change replan;
- migration-applied semantic decision directories, `docs/knowledge`, and two-hex machine-registry sharding with rollback and compatibility coverage;
- repository-scoped decision taxonomy with explicit routes, fail-closed classification, shared leaf enforcement, and no `foundation` fallback;
- lineage-bound refinement of the former operations leaf into trace, diagnostics, security, services, and storage, with recovery coverage for pruned shard parents;
- product-neutral starter taxonomies for fresh external repositories;
- Shiflo-driven hardening for legacy generation adoption, token-boundary lexical queries, large native build trees, and the complete local `init -> migrate -> lint -> query -> managed Codex/Claude run -> verification` path;
- observed rejection of a Claude content failure by project verification and successful isolated result-publication evaluation for Codex and Claude;
- repository-wide semantic relocation of classifiable documents, with unclassified or tied documents blocking completion;
- normalization of Claude rules and skills into provider-neutral instruction routes and `.agents/skills`, including brace-aware path conditions, exact reference repair, AGENTS routing, and a bounded CLAUDE import bridge;
- destination-bound Node reconciliation with bounded contiguous history backfill, closing the production gap where registered Hubs received no local managed-run events;
- provider-neutral, capability-free document normalization with resumable content-bound shards, exact per-source approvals, bounded topic splitting, portable-skill identity and resource bindings, durable apply, and stale lifecycle inspection;
- reviewed Shiflo and Lervo content migrations, including current replans, clean knowledge lint, and the full release-oriented repository suite.

See [ADR-0189](../decisions/knowledge/repository/0189-typed-repository-agent-surface-inventory.md), [ADR-0190](../decisions/knowledge/repository/0190-language-aware-bounded-repository-publication.md), [ADR-0191](../decisions/knowledge/repository/0191-bounded-hierarchical-repository-layout.md), [ADR-0192](../decisions/knowledge/repository/0192-repository-scoped-decision-taxonomy.md), and [ADR-0193](../decisions/knowledge/repository/0193-semantic-repository-and-agent-surface-migration.md).

## V0 completion

V0 acceptance completed on 2026-08-24. Reviewed normalization passed the complete Shiflo `migrate knowledge --provider -> review -> apply -> refresh -> lint -> current` cycle and the equivalent Lervo self-migration. Root and package READMEs document source-checkout installation without npm publication. See the [normalization acceptance evidence](../evidence/pilots/reviewed-document-normalization.md).

The language audit remains authoritative. The 2026-08-23 audit reports zero files and lines in runtime, test-fixture, and documentation categories. The English npm description, release manifest, and SBOM were regenerated and verified locally together; no package was published.

This is repository work, not a request for a hosted semantic product.

## Separate future scope

- Gemini and Copilot provider bridges.
- Fuzzy semantic merge or automatic fact promotion.
- External graph databases, embeddings, or Hub semantic services.
- Production credentials, external publishing approvals, and organization deployment policy.
- Automatic upgrades and multi-instance service orchestration.

Future scope requires measured need and a separate ADR; v0 does not inherit it implicitly.

## Acceptance gates

- Local `init -> migrate knowledge -> apply -> lint -> query -> managed run -> verification` succeeds without a Hub.
- User documents remain byte-safe unless exact approval authorizes a change.
- Normalization preserves section coverage, managed blocks, code and link coordinates, skill identity, and skill-resource lifecycle; Shiflo is no longer merely relocated legacy bytes.
- Codex and Claude pass shared contracts.
- A clean clone or another Lervo installation reproduces tracked knowledge.
- Generated documents remain English, bounded, and idempotent.
- No dormant documentation or feature directory is created.
- Documentation lifecycle, typecheck, targeted tests, build, and applicable distribution checks pass.
