# Lervo v0 roadmap

Status: `complete`
As of: 2026-08-25

## Goal

Deliver a local-first, provider-neutral workflow that initializes repositories, compiles knowledge, runs Codex or Claude under explicit policy, verifies changes, retains evidence, and optionally coordinates through a Hub.

- Self-migration, lint, and zero-change replan completed.
- Semantic decision directories, `docs/knowledge`, two-hex registry sharding with rollback and compatibility, explicit repository taxonomy, fail-closed routing, shared-leaf enforcement, and removal of the `foundation` fallback completed.
- Lineage-bound operations were refined into trace, diagnostics, security, services, and storage, including pruned-parent recovery and product-neutral starter taxonomies.
- Shiflo supports legacy adoption, token-boundary queries, large native build trees, and the complete local `init -> migrate -> lint -> query -> managed Codex/Claude run -> verification` path.
- A Claude content failure was rejected. Isolated result-publication evaluation succeeded for both providers.
- Repository-wide relocation covers every classifiable document; unclassified or tied documents block completion.
- Claude rules and skills were normalized into provider-neutral routes and `.agents/skills`, preserving brace-aware conditions, references, AGENTS routing, and a bounded CLAUDE bridge.
- Destination-bound Node reconciliation supports bounded contiguous-history backfill.
- Provider-neutral, capability-free normalization supports two-document/32-KiB batches, three-way concurrency, exact cross-snapshot document caching, single-document retry subdivision, exact per-source approval, semantic bounded splitting excluding root README, portable-skill and resource binding, exact lifecycle-metadata preservation, whitespace rejection, durable apply, and stale lifecycle inspection.
- Reviewed Shiflo and Lervo migrations, current replans, clean lint, and the release-oriented suite completed.
- Fail-closed Codex and Claude prompt/Stop hooks preserve provider settings through exact approval, provide immediate one-time Codex `/hooks` trust guidance, and remain non-ready until every provider event is observed.
- Terminal hook contract v2 provides a terminal-only bundle, installs an integrity-bound repository-local runtime, resolves the Git root from provider subdirectories, migrates bare contract-v1 commands, and reconciles replay-safe generated-runtime upgrades without a global CLI `PATH`.
- Privacy-bounded unmanaged terminal history and coverage distinguish preparation and exact output reference from unsupported acceptance, managed delivery, and internal use.
- Renderer-hidden markers retain legacy v1 parsing and distinguish structural publication from full-query snapshot semantics.
- Managed E1–E4 grounding provides exact-version delivery, output citations, separate metrics, and one local/Hub projector.
- Structured revisioned workstreams provide repository-wide continuation discovery, explicit ambiguity handling, source-less first checkpoints, CAS/event binding, managed E1–E3 delivery, bounded unmanaged preparation, conditional changed-turn revision advancement, structured pending user items, exact-revision finalization declarations, and automatic cross-provider deliberation-suite resolution.

## Separate future scope

- Gemini and Copilot bridges.
- Fuzzy semantic merge or automatic fact promotion.
- External graph databases, embeddings, or Hub semantic services.
- Production credentials, external publishing approvals, and organization deployment policy.
- Organization-wide fleet policy and unattended cross-version rollout beyond repository-scoped automatic runtime reconciliation.

Future scope requires measured need and a separate ADR; v0 does not inherit it.

## Installed follow-up acceptance

The live gap found on 2026-08-25 is closed. Historical event-schema compatibility repaired Shiflo without rewriting canonical events; the verified standalone Hub was upgraded; scoped workstream authority was migrated; and repository-specific Shiflo and Lervo Node services remained concurrently ready. The legacy singleton was removed only after replacement readiness. ## Acceptance gates

- Local `init -> migrate knowledge -> apply -> lint -> query -> managed run -> verification` succeeds without a Hub.
- User documents remain byte-safe without exact approval.
- Normalization preserves section coverage, managed blocks, code and link coordinates, skill identity, and skill-resource lifecycle; Shiflo is not merely relocated legacy content.
- Codex and Claude pass shared contracts.
- A clean clone or another installation reproduces tracked knowledge.
- Direct Codex and Claude prompts invoke the repository-local hook or fail closed without a globally discoverable `lervo`; installation reports the provider-native trust action, readiness remains incomplete until contract-v2 invocation evidence exists, and sessions remain unmanaged.
- Generated documents are English, bounded, and idempotent.
- No dormant documentation or feature directory is created.
- Documentation lifecycle, typecheck, targeted tests, build, and applicable distribution checks pass.
- Natural-language capability selection remains deterministic and evidence-bound; deleting `.lervo/state` preserves durable data and permits projection reconstruction.
- An agent can upgrade an initialized repository through `lervo upgrade`; same-version rebuilt Node payloads reconcile by hash, while CLI acquisition and non-Lervo authority remain explicit.
- CLI, Hub, and Node release validation uses the supported runtime boundary rather than the checker's built-in inventory; Node 22.13 packed consumers run with empty stderr, and temporary deployment works across Windows volumes.
