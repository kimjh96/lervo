# Lervo v0 roadmap

Status: `complete`
As of: 2026-08-25

## Goal

Deliver a local-first, provider-neutral workflow that initializes repositories, compiles knowledge, runs Codex or Claude under explicit policy, verifies changes, retains evidence, and optionally coordinates through a Hub.

## Repository-knowledge hardening

Completed on 2026-08-23:

- Bounded typed discovery covers sensitive logs and provider surfaces. Publication defaults to English with language auditing, bounded navigation, safe stale-output deletion, minimum initialization, and lazy directories.
- Migration handles missing README and AGENTS, a separate CLAUDE bridge, bounded root entrypoints, and current documentation contracts.
- Complete test, build, release-artifact, SBOM, attestation, distribution, packed-CLI, documentation, and brand checks passed. English migration covered runtime, fixtures, documentation, and historical ADRs; every audit category reached zero.
- Self-migration, lint, and zero-change replan completed.
- Semantic decision directories, `docs/knowledge`, two-hex registry sharding with rollback and compatibility, explicit repository taxonomy, fail-closed routing, shared-leaf enforcement, and removal of the `foundation` fallback completed.
- Lineage-bound operations were divided into trace, diagnostics, security, services, and storage, including pruned-parent recovery and product-neutral starter taxonomies.
- Shiflo supports legacy adoption, token-boundary queries, large native build trees, and the complete local `init -> migrate -> lint -> query -> managed Codex/Claude run -> verification` path.
- A Claude content failure was rejected; isolated result-publication evaluation succeeded for both providers.
- Repository-wide relocation covers every classifiable active document. Canonical archive and inherited collections remain; other unclassified or tied documents block completion.
- Claude rules and skills were normalized into provider-neutral routes and `.agents/skills`, preserving brace-aware conditions, references, AGENTS routing, and a bounded CLAUDE bridge.
- Destination-bound Node reconciliation supports bounded contiguous-history backfill.
- Provider-neutral, capability-free normalization supports two-document/32-KiB batches, three-way concurrency, exact cross-snapshot document caching, single-document retry subdivision, exact per-source approval, and semantic bounded splitting excluding the root README and pull-request template. It preserves host-aware heading policy, portable-skill and resource binding, exact lifecycle metadata, whitespace rejection, durable apply, and stale lifecycle inspection.
- Reviewed Shiflo and Lervo migrations, current replans, clean lint, and the release-oriented suite completed.
- Availability-safe Codex and Claude direct hooks preserve provider settings through exact approval, provide immediate one-time Codex `/hooks` trust guidance, and remain non-ready until every provider event is observed. Prompt preparation is current-repository retrieval only; root Stop lifecycle gaps are audited without blocking, while malformed endpoint input and attached-worker isolation remain fail-closed.
- Terminal hook contract v2 supplies a terminal-only bundle, installs an integrity-bound repository-local runtime, resolves the Git root from provider subdirectories, migrates bare contract-v1 commands, and replay-safely reconciles generated-runtime upgrades without a global CLI `PATH`.
- Privacy-bounded unmanaged terminal history and coverage distinguish preparation and exact output reference from unsupported acceptance, managed delivery, and internal use.
- Renderer-hidden markers retain legacy v1 parsing and distinguish structural publication from full-query snapshot semantics.
- Managed E1–E4 grounding provides exact-version delivery, output citations, separate metrics, and one local/Hub projector.
- Structured revisioned workstreams provide repository-wide continuation discovery, explicit ambiguity handling, source-less first checkpoints, CAS/event binding, managed E1–E3 delivery, bounded unmanaged preparation, conditional changed-turn revision advancement, structured pending user items, exact-revision finalization declarations, and automatic cross-provider deliberation-suite resolution.
- Typed same-provider semantic grounding controls managed workforce planning, capability activation, and deliberation routing. Direct terminal source selection uses a separate provider-neutral query projection that grants no effect, authority, external route, or durable instruction. Raw-language lexical matching retrieves candidates only; exact protocol coordinates are the only string-matched authority inputs. Terminal candidate, selected, loaded, hook-prepared, provider-injection, and provider-use states remain distinct.
- Repository-scoped Hub workstream replication spans separately authorized Node event streams with exact content hashes, automatic Node publication and import, bounded divergent heads, dedicated permissions and health, and no transfer of approval authority.
