# Readiness and preflight

Node readiness binding and final preflight are implemented. Raw task observations bind to the combined authority/task digest, with exact responsibility scope checked. Capability-derived CLI, write, and network-source checks are mandatory.

Node independently checks canonical assignment revisions, leases, worker ancestry, registered Git workspace ownership and state, and the latest responsibility binding history and CAS artifact.

Both execution preflights supplement positive application evidence with configured provider and verification-tool version probes and read-only control-repository knowledge currency inspections. Knowledge inspections require stable, complete scans, no pending normalization, and zero lint issues; they do not prove worker context delivery.

Native Codex and Claude login-status probes supplement positive provider evidence using explicit host profiles and redacted results. Stored-login presence proves neither server authentication nor task-tool permission.

On both preflights, verification-definition inspections require every responsibility suite to match trusted host hash pins and have safe working directories. They execute no verification command and do not prove verification success.

Read-only filesystem access observations supplement read/write scope evidence for exact plan and responsibility paths in the registered Git workspace. They reject unsafe aliases and repeat before effects. Directory-boundary and Node-process access prove neither worker sandbox nor external-tool permissions.

Step 2 still requires production responsibility installation, remote authentication and actual task-tool permissions, task-specific knowledge delivery and source-policy/verification/budget/process observations, and non-Git host composition. Disposable-worktree evidence does not prove an installed worker can execute.
