# Installed acceptance

| Scenario | Passing evidence |
| --- | --- |
| One short research request | Reads prior decisions, allocates ready staff, checks sourced artifacts, and returns a reviewed answer without user dispatch prompts. |
| Existing suitable staff | Reuses an available qualified worker without duplicate hiring. |
| Skill/capacity gap | Records alternatives, hires within policy, proves readiness, and obtains the artifact. |
| Owner-defined duties | Revises responsibilities within mandate without human reapproval; resolves affected leases first. |
| Worker permission failure | Detects readiness or start failure, repairs or separates responsibilities within authority, and continues. |
| Provider failure without reply | Durable failure wakes the owner; known-safe retries are bounded, and uncertain effects are inspected. |
| Weak result | Provider exit and lint cannot complete the goal; rejected acceptance causes bounded rework. |
| Central and direct intake | Uses one product owner and assignment set; escalation never widens a repository lease. |
| Restart/duplicate delivery | Causes no lost failure, duplicate hire or provider effect, or concurrent owner decision. |
| User changes requirement | Revises exact plans and contracts while independent work continues. |
| Revocation/budget/cancellation | Stops admission, reports missing usage, and reconciles in-flight effects. |
| Platform replacement/idle | The same contract works locally without Hub and through Discord. Unchanged idle periods cause no model calls or repeated history reads. An unaddressed agent-authored reply must not trigger unsolicited acknowledgement loops, while exact participant mentions and human reply ownership continue to work. |
| Native Discord `/goal` | Guild command is registered for the installed supervised owner, acknowledges within three seconds, attributes the human request to the exact visible source message, binds through the same canonical writer as local stdin, reports failed intake truthfully, and replies with independently verified result and publication evidence. An uncertain acknowledgement does not create a duplicate request. A completed locally bound goal remains intact when a new Discord request starts a distinct successor workstream under separately reviewed authority. |
| Result delivery failure | Retains accepted work and retries publication only; acceptance is not delivery success. |

Use common provider/host contract fixtures. Record bundle/source, role/mandate hashes, causal links, artifacts, acceptance, failures, and missing observations. Measure goal completion, human interventions, redundant hires, duplicate effects, recovery time, model calls, and observed token scope. Improvement claims require an equivalent baseline.
