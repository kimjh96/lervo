# Contextual reporting acceptance

Replace the unconditional footer in `apps/node-runtime/src/conversation-repository-work-responder.ts` with evidence-aware response composition. Preserve canonical change observations as inspectable evidence. Apply the shared writing contract across providers and hosts; Discord formatting must not impose Korean stock prose on other languages.

Verify these scenarios:

- Ordinary conversation.
- Research without edits.
- A verified code change.
- A requested change with no resulting edit.
- A failed save.
- Unknown verification.
- Explicit requests for changed files.

Replies must convey the relevant outcome and material limitations without mandatory status suffixes or duplicate file lists. Check meaning and evidence fidelity, not a new exact sentence.

Cached/replayed responses and platform truncation must preserve these semantics. Keep historical artifacts unchanged and identify legacy presentation before re-rendering. Explicitly scope cache migration during implementation so old fixed footers are not mistaken for user-authored prose.
