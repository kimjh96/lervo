# Multi-team agent organization

Part of [Paperclip-, Buzz-, loop-, graph-, and host-product outcomes](../host-products.md).

State: `delivery required`.

## Outcome

One human owner operates a Lervo organization with central leadership and several repository-backed project teams. Each hired expert agent retains a durable unique name and identity, exact role history, provider-neutral context, one-to-one external bot identity, explicit channel membership, and scoped authority. One named central agent appointed to the CEO responsibility coordinates teams and performs reviewed organization and Discord administration within policy.

## Current foundations

Implemented foundations include:

- Workforce identity, roles, assignments, handoffs, workstreams, and approvals.
- Bounded scheduling and graphs, provider-neutral deliberation, and per-bot Discord deployments.
- Exact agent and role hashes in conversation records, agent-bound managed read-run causality, and bounded agent-specific recent conversation input.
- Repository-local append-only contracts for teams, agent membership, external deployment, channel membership, and deliberation participation.
- Reviewed agent-context promotion, deterministic projection, explicit successor handoff, bounded Node materialization, and same-turn managed context injection.
- A read-only multi-repository organization operating report, explicit central/project team-kind revision, distinct agent display identity, conservative built-in CEO role, and fail-closed executive policy evaluator.
- Product-host v7 organization-inspection routes and an installed exact-effect execution boundary with durable replay-safe Discord channel and thread adapters.
- Bounded authoritative reconciliation of uncertain managed deliberations with managed user-visible completion or attention signals.

The CLI can bind current hired agents and Discord deployments. An organization-configured Node fails closed on identity mismatch. These foundations do not complete the outcome.

## Completion criteria

1. Bind at least one central repository and the Shiflo and Plen repository teams, then run the implemented multi-team operating projection against them.
2. Extend the installed executive effect boundary from allowlisted Discord channel and thread administration to delegation and approval effects without exposing credentials.
3. Promote reviewed context through real conversation and change turns; verify restart, retirement, and explicit successor handoff.
4. Support natural addressed routing for participants, roles, teams, and bounded discussion groups.
5. Install a scenario with a human, a uniquely named central agent appointed to the CEO role, and at least two project teams whose agents collaborate without crossing authority or context boundaries.
6. Demonstrate two distinct installed agent bots completing bounded deliberation in one real Discord channel and stopping at its terminal condition.
