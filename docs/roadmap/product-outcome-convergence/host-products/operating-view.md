# Unified operating view

Outcome: an operator sees objectives, agents, assignments, dependencies, blockers, approvals, verification, and observed budgets together.

State: `delivery required`.

The static board covers the graph; protocol-v2 attention covers current authority and knowledge maintenance through installed read-only routes. These remain separate projections, not one interactive surface.

Lervo owns a first-party reference composition and continues to support separately installed hosts. Discord must first expose material objective, staff, work, blocker, approval, verification, usage, cost, and result states in a usable native projection. The future first-party surface then composes the same commands, queries, subscriptions, source coordinates, and observability into an interactive operating view without acquiring repository authority.

Acceptance follows the [Discord-first reference-product roadmap](discord-first-reference-product.md) and [product-surface specification](../../../specifications/execution/product-surfaces.md).
