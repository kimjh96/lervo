# Installed compiler function attribution

Status: `partial`
As of: 2026-10-12

This supplements [installed recording-cost attribution](installed-recording-cost.md). It does not qualify a performance repair. Sixteen cold workers use the unchanged installed CLI and Node graphs on Node 26.5.1 and 22.13.0, with 4 KiB and 12 KiB profiles and recording off/on at the same fixture path. All sixteen event/body references pass parent and independent immutable-database audits. No request, storage or code cache is primed.

## Method and limits

V8 function, code and source logging records function names, source positions, reported durations and logger timestamps. Unique synthetic scripts mark the start and end in the same logger clock. Marker script events are excluded by script ID; other logging and observer overhead remains. Original operations, guards, synchronization, complete reads and ordinary close remain intact.

The timestamp identifies a logging event, not necessarily the start of a compilation job. Category durations are kept separate: parsing can contain other parsing work, and optimized compilation can run in the background. They are not summed into main-thread CPU or predicted removable wall time. Anonymous and unresolved script entries remain in the observations without guessed ownership. Node's [V8 logger](https://raw.githubusercontent.com/nodejs/node/v22.13.0/deps/v8/src/logging/log.cc) defines the event fields; its [compiler implementation](https://raw.githubusercontent.com/nodejs/node/v22.13.0/deps/v8/src/codegen/compiler.cc) records compilation-stage durations in milliseconds.

## Findings

Recording adds many small first-use functions, rather than another single large coordinate-validator compilation. Node 26 control workers report 341–344 `parse-function` events, versus 498–501 with recording; Node 22 reports 331–332 versus 489–499. These are event counts, not distinct functions or a measured CPU delta.

Exact installed assignments map generated `de` to `event`, `we` to `contextQualityPreparedEventPayload`, `Pe` to `contextQualityVerifiedEventPayload`, and `Z` to the private coordinate v6 validator. These categories are not additive savings estimates. Other additional work includes event publication, payload checks, report decoding, storage admission and Node internals.

A scratch Ajv build tests `inlineRefs: false` as a way to reduce generated code. All 227 bounded selected-map differential cases match. This is no shared-runtime candidate, so no resource comparison is run. The initial importer accidentally rewrote embedded source strings and failed before compilation; its correction changes only imports in the module header. Original source and generated artifacts remain unchanged.

## Duplicate compression removal

The private report codec now validates, copies and hashes input before repository lookup. Existing reports still receive complete decompression and hash verification. A valid duplicate returns without recompression; a new report is encoded from the captured bytes. No package export, storage format, event, authority cache or durable state is added. Transaction poisoning and both complete per-call reads remain intact. This bounded work reduction is retained in source, without claiming that it repairs the overall resource regression.

Both Node versions pass 190 focused adapter, storage and recording tests, including corrupt duplicates, caller mutation during lookup, input limits, rollback, expired methods and post-commit confirmation. Fourteen old/new codec comparisons per runtime preserve exact encoded headers and chunks through 1 MiB random input. Formatting and a rebuild preserve the same runtime graph bytes.

Thirty-two separate CLI/Node observer workers preserve 464 event/body references and 928 complete native SQL reads. Compression runs 314 times, exactly once per unique stored body, avoiding 150 repeated encodings. Concurrent workers compress 36–38 unique bodies for 56 accepted reports while retaining 112 full reads. Cold workers have two distinct reports and still perform two compressions and four reads.

An isolated microbenchmark measures seven interleaved pairs for each body shape and size. It uses one pre-inserted body, in-memory SQLite, private repository methods and no-op lifetime guards; each duplicate still receives two full reads. Median per-duplicate times for random 64 KiB bodies decrease from 0.711 to 0.211 ms on Node 26 and from 0.631 to 0.220 ms on Node 22. Random 1 MiB bodies decrease from 14.293 to 2.810 ms and from 14.711 to 3.100 ms. Repeated-byte bodies also improve in these observations. These figures describe duplicate work, not durable publication or a cold request.

The separate 96-worker CLI comparison retains 1,392 event/body references. Candidate cold added means remain 11.430–12.441 ms, and concurrent whole-process ratios remain 1.238–1.281. Recorded request times do not improve consistently. All samples remain, including adverse values; no frozen gate is reclassified. The comparison uses the preceding installed CLI and new canonical scratch builds, not a new installed release.
