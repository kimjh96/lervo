# Provider instructions and reply fitting

`apps/node-runtime/src/conversation-repository-work-writing.ts` instructs immediate inspection and work, an early checkpoint after the first material edit, and bounded finalization. Pending mode delegates global convergence to the host and prohibits claiming knowledge currency while pending. Synchronous mode retains current-scope lifecycle work. Replica parity and canonical completion are described as host-owned post-exit publication gates.

External-effect instructions require an explicitly requested commit, remote creation, push, or deployment, even for an authorized requester. Deployment additionally requires a target, rollback, current authority and runtime checks, and installed verification. The responder treats humans as authorized requesters and accepts exact configured participant/role/conversation matches. These instructions do not prove adapter or external-system enforcement.

Other instructions distinguish:

- Turn-local tool visibility from authorization.
- Repository-scoped counts from organization inventory.
- Request, start, effect, completion, failure, and publication times.

They prohibit inferring a common cause or platform absence from generic historical failure codes.

Instruction history includes at most four recent turns, each sliced to 2,048 characters, and eight durable results, each sliced to 1,024 characters and reversed for presentation. These excerpts provide context, not complete historical evidence.

The prompt requests a concise reply in the conversation language below 1,500 characters. Separately, `fitDiscord` trims text, replaces em dashes with hyphens, and limits output to 1,950 Unicode code points. Oversized output is sliced with reserved space and receives a fixed Korean truncation notice. The fitter neither enforces the prompt's 1,500-character target nor selects the notice language from the request.
