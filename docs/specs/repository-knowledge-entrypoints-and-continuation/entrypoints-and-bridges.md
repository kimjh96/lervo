# Canonical Entrypoints and Provider Bridges

Initialization creates no root documents. Before structural publication, canonical instruction bootstrap inspects exact AGENTS and CLAUDE bytes.

If AGENTS is absent and CLAUDE is a safe shared candidate, one exact-approved stage creates AGENTS from unchanged CLAUDE bytes plus a separate managed route, leaving CLAUDE unchanged. Provider imports or managed blocks make adoption unresolved. Otherwise, first migration creates short English README and AGENTS only when missing. Existing entrypoints remain user-owned until dedicated review.

`knowledge instruction bridge --provider claude` accepts AGENTS only from a bounded instruction or structural hash. An adopted exact duplicate may become the approved thin bridge. Mixed user content retains its bytes around one managed import. Structural migration never translates existing bytes.
