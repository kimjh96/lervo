# Lifecycle and completion

First reconcile structural/bootstrap/layout prerequisites; perform canonical review and integration; normalize and apply accepted document families; then reconcile bridges and structural projections, run lint, and replan currency. Each stage follows ADR-0303's owned-error and rollback rules. Unrelated warnings remain visible. Repository completion requires zero lint errors and current required stages.

Capture source and context hashes before disclosure and recheck them after provider work, before integration, and inside the settlement fence. Lifecycle inspection binds matching before/after scans and the resulting source snapshot. Changed source becomes `stale`; an expired lease loses settlement authority. A pass on unrelated newer source cannot validate an older review.

A change obligation completes only when every source partition has a semantic disposition, every required canonical edit is integrated, every required normalization family is current, ordered lifecycle verification passes, and all bindings still match. A partial workset never closes repository debt. Global currency also requires a complete current baseline and no unresolved applicable canonical candidate or authority decision. Status keeps source-scoped completion and global currency separate.

Background writes emit ordinary change evidence with causal links to the parent obligation. Exact normalization outputs already covered by the same apply receipt are not regenerated as fresh debt. Genuine new semantic changes remain reviewable. Rejected or unchanged candidates cannot cause an infinite write/normalize loop.
