# Scoped writes and integration

Canonical drafts and normalization candidates remain private until reviewed. Canonical source edits require isolated managed workspaces, scoped path leases, sealing, required verification, and an exact integration plan. A result branch or accepted artifact alone is not integration.

The integrator binds the current target revision, complete changed-path union, original and desired bytes, role/delegation, approvals, document-layout permit, and verification. Normalize complete document families, including split destinations and managed package metadata. Apply through the existing durable knowledge journal under path-conflict and target-generation fences.

Never replace a shared checkout, stash user work, force a ref, or bypass dirty-target evidence to land a candidate.

Immediately before mutation, recheck target, source, protected user-region, resources, approvals, and leases. Overlap with a live writer waits; a changed target invalidates the plan. Seal and integrate canonical edits through the existing integration adapter. Apply normalization through the existing exact document transaction. Both require proof that desired bytes reached the canonical repository. Disjoint user changes require a fresh exact plan, not inherited snapshot approval.

Recovery inspects the journal, target bytes, source/result hashes, and event receipts. An interrupted apply resolves to proved applied, proved rolled back, or `recovery_required`. Recovery cannot rerun a model, overwrite uncertain bytes, or mark the stage complete from file presence alone.
