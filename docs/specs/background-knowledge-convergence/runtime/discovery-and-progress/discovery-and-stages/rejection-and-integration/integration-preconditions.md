# Integration preconditions

Before acquiring a canonical writer lease, the runtime compares every reviewed target preimage with the selected Git integration ref. Only exact, canonically settled normalization lineage can explain an owned preimage change.

Before recording a mismatch, the runtime attempts one synchronization of the integration ref with `HEAD`. It merges `HEAD` only when every ref-only change matches an integrated draft that reached root apply ([ADR-0449](../../../../../../decisions/knowledge/repository/canonicalization/0449-synchronize-integration-target-with-working-branch.md)).

A delegation can name a host-local ref that this host never created. Synchronization starts an absent ref at `HEAD` with a create-only ref update. If the ref still cannot be resolved, the stage records `attention_required/knowledge_integration_target_unavailable` until the delegated ref exists ([ADR-0472](../../../../../../decisions/knowledge/documents/0472-start-absent-integration-refs-and-bound-untyped-stage-failures.md)).

When the ref is not synchronized, the runtime checks whether a squash merge absorbed it. Every ref-only path must be byte-equal at `HEAD`, changed by a base-side commit, or committed only by Lervo and never adopted, and at least one path must have been decided by the base. The runtime then keeps the old tip under `refs/lervo/knowledge-integration-absorbed/`, moves the Lervo-only ref to `HEAD` with a compare-and-swap, and records `knowledge.integration_target.absorbed`. It never touches the working tree or a user branch ([ADR-0482](../../../../../../decisions/knowledge/semantics/0482-absorb-squash-merged-semantic-candidates-and-type-verification-source-changes.md)).

When `HEAD` is an ancestor of the ref, each ref-only path holding an integrated draft that the working tree no longer holds returns to `HEAD`'s committed bytes in one Lervo commit on the ref. Drafts the working tree still holds stay ([ADR-0530](../../../../../../decisions/knowledge/maintenance/0530-keep-background-knowledge-moving-past-divergent-targets.md)).

Other mismatches park the batch instead of waiting. The batch integrates nothing; its candidate sources park as `target_diverged` with the exact divergent target ref, path, and hash; its other decisions keep coverage; and the cursor moves on to the next workset or to normalization. A changed source or changed target bytes readmit a parked source ([ADR-0530](../../../../../../decisions/knowledge/maintenance/0530-keep-background-knowledge-moving-past-divergent-targets.md)). Stalls recorded as `waiting_authority/canonical_target_diverged` before this change are reevaluated once and then park.

Unchanged drafts are invalid semantic changes and cannot start an empty Git integration.

Before acquiring a writer lease, the runtime also evaluates the complete approved batch against the current projected document layout. Capacity-only failures park candidate sources as `layout_capacity_exceeded`, preserve other decisions, integrate no drafts, and advance to the next workset or normalization. The private `layoutCapacityHash` binds routes, roles, capacity policy, and observed counts. Source changes or a changed layout hash readmit the source. The disposition ledger retains noncandidate decisions while excluding every parked draft. Under the ADR-0547 amendment recorded in [ADR-0532](../../../../../../decisions/knowledge/maintenance/0532-continue-background-review-past-capacity-and-optional-context-failures.md), only overflow a write creates or grows blocks it. [ADR-0583](../../../../../../decisions/knowledge/repository/layout/0583-hold-moves-that-overfill-a-directory-and-report-existing-overflow.md) reports untouched overflow as a non-blocking advisory and a lint warning. Existing unrelated overflow therefore does not by itself block a write elsewhere. Adding, moving, or creating a document in a full directory still blocks, even when another deletion there keeps the count equal. Existing over-capacity canonical folders remain separate layout debt; this rule moves no documents, and apply-time capacity evaluation follows the same amended boundary.

An older capacity stop may have completed ref integration before root apply rejected its layout. The runtime validates the exact retained proof, unchanged root preimages, and ref draft hashes, then uses ADR-0530 restoration to return only those paths on the delegated ref to committed `HEAD` bytes. A compare-and-swap protects a concurrent ref move. Root bytes and the working branch stay unchanged. Private `retiredRefEffect` evidence records the ref transition and restored paths before the batch parks.
