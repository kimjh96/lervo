# Rejection and integration preconditions

ADR-0435 retains rejected canonical batches while routing independent normalization debt to its own review pipeline. The `canonical_review` receipt binds a private `rejection_retained` proof and authorizes no integration. Exact historical rejections are reused without another model call. Ordered projection maintenance may proceed, but final lifecycle verification remains `attention_required/knowledge_semantic_review_rejected`. Rejected and unassessed sources count toward neither semantic coverage nor baseline `current`.

Before acquiring a canonical writer lease, the runtime compares every reviewed target preimage with the selected Git integration ref. Only exact, canonically settled normalization lineage can explain an owned preimage change. Before recording a mismatch, the runtime attempts one synchronization of the integration ref with `HEAD`. It merges `HEAD` only when every ref-only change matches an integrated draft that reached root apply ([ADR-0449](../../../../../decisions/knowledge/repository/canonicalization/0449-synchronize-integration-target-with-working-branch.md)). Other mismatches record `waiting_authority/canonical_target_diverged` with a private exact target-ref/commit dependency. Source or target-ref changes trigger reevaluation. Matching target bytes resume the existing review without another model call. Unchanged drafts are invalid semantic changes and cannot start an empty Git integration.
