# Project CAS retention

The project content-addressed store (CAS) holds immutable artifact bytes. [ADR-0534](../../../decisions/operations/storage/0534-bound-installed-runtimes-and-convergence-artifacts.md) extends typed derived-state and checkout retention to obsolete convergence artifacts. [ADR-0584](../../../decisions/operations/storage/0584-let-cas-retention-finish-a-pass-on-a-live-host.md) lets a pass finish while the host keeps writing. [ADR-0585](../../../decisions/operations/storage/0585-release-mirrored-backups-and-settled-assignment-inputs.md) releases mirrored event-writer backups and settled assignment inputs. [ADR-0586](../../../decisions/operations/storage/0586-release-superseded-stage-records.md) releases the stage results, failure proofs and provider stage observations of superseded stages. Events remain immutable. General `.lervo/data` pruning remains unauthorized.

## Exact reachability

1. A candidate must already exist as a regular CAS object and be named by `inputArtifactHash`, `resultArtifactHash`, `dependencyHash` or `evidenceHash` in a convergence baseline or stage event. A released record of a superseded stage (rule 8) is also collectable. Other CAS objects are always retained, including objects not yet published by their writer.
2. For every open obligation, every hash or CAS URI anywhere in its event payloads is a root. For every settled obligation, the latest stage whose state is neither `queued` nor `running` roots its entire payload. Settlement includes current, superseded and attention outcomes.
3. Every successful `normalization_apply` stage and every current `canonical_integration` stage roots its payload, including its input, result and receipt graph. Later stages always follow `canonical_integration`, so the latest settled stage never covers the integration batch that the canonical disposition ledger replays. Every convergence terminal payload is a root, preserving historical lifecycle receipt digests. The latest `knowledge_sources_parked` stage also roots its payload for carry across obligations.
4. Every non-convergence event payload remains a root, regardless of age, except the `convergenceInputArtifactHash` of a convergence `assignment.created` event. That input joins its obligation's references: a root while the obligation is open, then only as part of the latest settled stage. An input named after settlement stays a root. All noncandidate CAS objects remain roots for their embedded references, including completed provider results. An archived assignment, matched to its creating event by assignment and obligation, does not root its own input.
5. Files under `.lervo` and the repository coordination home root their embedded hashes and CAS URIs. An `events` row in `<data>/event-writer-backups/<name>/events.sqlite` roots nothing when the live snapshot holds the same event: the same identifier, sequence, hashes, envelope fields, actor and payload. Any other backup row, or a row that fails to read, roots everything it names. A cached backup scan also binds the device and inode of the live event database; the append-only `events` triggers exclude rewriting a row in place. This covers normalization and canonicalization candidates, instruction capture, terminal evidence, materialization journals, provider review caches, workforce records, workspace records and recovery checkpoints. SQLite tables are read as logical cells, including long values spanning overflow pages. Event storage is read through the canonical event interface; SQLite report bodies are followed through the report reader.
6. References use `sha256:<64 hex>` or `lervo-cas://sha256/<64 hex>`. The collector follows candidate-to-candidate references to a fixed point. It scans retained object bodies conservatively, so incidental matching strings may retain extra objects.
7. Only unmarked candidates whose object modification time and latest direct convergence reference are both older than fourteen days may be unlinked. For a released record, the latest event of its own assignment that names it replaces the convergence reference. Unknown artifact ownership is protection, never deletion authority.
8. A convergence assignment's stage is superseded when its obligation has settled, the assignment was created before that, and the last settled stage record names neither the assignment nor its input. A record of a superseded stage is released only when its body matches its digest, parses, and has every expected field. A stage result or failure proof must be named by its own assignment's `assignment.completed` and by no other assignment's completion. A provider stage observation must name its assignment and that assignment's input. A released record's references are edges. Its assignment's own events and archive do not root it; every other record still does. An unknown, unparseable, mismatched, ambiguous or larger-than-32-MiB body stays protected. The scan projection caches each verified shape by digest in `records`.

CAS temporary publication files, query indexes, convergence checkout contents, collector projections and worker lock files are outside reference-body scanning. Query indexes are rebuildable and do not own artifact lifetimes. Their canonical inputs remain roots. macOS AppleDouble files, named `._<name>` and starting with the magic `00 05 16 07`, are not reference files. A zero-byte SQLite file without a WAL is an empty store. Links, unreadable reference files or exceeded inventory limits stop the pass. A reference file that changes, vanishes or holds its SQLite writer lock during its read restarts alone; that cycle sweeps nothing. An invalid collector projection starts a fresh reference scan. No object from another subsystem is selected for deletion merely because it has no observed reference.

## Background bounds and failure

Every resident host runs collection through `withRepositoryKnowledgeWorkerLock`, before convergence ownership selection. It never nests the lock. A busy lock produces no status. Cancellation, developer work, scheduler yield or an active/recoverable materialization defers collection.

Each slice scans at most 16,384 chunks of at most one MiB, at most 512 MiB of file or SQLite-cell bodies in total, and at most 4 s of read time. Yield probes run between chunks, at most once per 100 ms of read time, and their time is not read time. A logical SQLite chunk has at most 128 rows and one MiB of string or blob cells. The sweep unlinks at least thirty-two objects unless it yields or the head moves, then continues until five seconds after the pass began, with a backstop of 4,096 unlinks; it probes live work at most once per 100 ms ([ADR-0660](../../../decisions/operations/storage/0660-keep-cas-retention-due-until-the-store-settles.md)). Metadata inventory permits at most 100,000 files/directories; event and report reference inventories permit at most 200,000 records each. These are separate bounds, not a claim that complete metadata replay finishes in 100 ms. Immutable SQL report references have their own resumable digest cache. Each cycle makes at most sixty-four report lookups. Report bodies have a separate eight-MiB cycle budget, a separate 100 ms of lookup time and the existing one-MiB per-report limit. The current `context-quality-admission.ts` and `context-quality-commit.ts` writers append a publication event in the same transaction as each SQL report, so every stored report has a canonical event root. A completed pass waits twenty-four hours before a new scan. Further sweeps of the same pass reuse its completed scan. While a pass leaves work, the resident's change fence makes the next slice due 30 s after the observation, and a full cycle whose own pass left work schedules the next one 30 s after it ends. This holds when the resident is idle or its provider stages wait; a pass the cycle did not run, as on a held or off-base checkout, schedules nothing.

The private scan envelope requires `scan` and a SHA-256 `checksum` of its exact JSON serialization. `scan` requires `schemaVersion: 1`, `nextScanAt` in epoch milliseconds, `eligible` hashes, `files`, and `reports`. Each file entry binds `identity`, `complete`, byte `offset`, bounded overlap `tail`, and candidate `references`; a completed entry keeps an empty `tail`; SQLite entries also bind table and row cursors. Each report entry binds `referenceSeq` and either immutable `references` or an observed absence. The optional `records` map binds a CAS digest to a verified `kind`, `assignmentId` and `binding`, to `null` for a body that is no releasable record, or to `no_observation_prefix` when only its first bytes were probed; its entries outlive a pass while their object exists. Absolute reference paths and hashes stay only in this private projection. Fixed `.next` files are replaced and excluded from roots, so an interrupted projection cannot pin its own candidates.

One checksummed scan projection is limited to 32 MiB. Each cached body scan binds the exact file identity, size and modification/change times. SQLite identities include the WAL identity. A changed body restarts its scan while the other files keep their progress. A path that vanishes during the inventory walk is skipped. The canonical replay visits a snapshot that ends at the observed head, and an event appended during it does not fail the pass. The final inventory and event head must still agree before deletion. The collector does not change references or event history. An interrupted unlink leaves only unreachable objects for a later pass.

`cas-retention-observation.json` replaces one bounded local observation. Required fields are `schemaVersion: 1`, ISO `observedAt`, `status: yielded|collected|unavailable`, `failure`, integer `removedObjects` and integer `reclaimedBytes`. `failure` is `bound_exceeded`, `failed`, `no_space`, `unreadable_reference`, `unsafe_reference`, `unsupported_reference`, `unstable_reference` or null. Optional boolean `remaining` is true when the pass stopped with unclassified records, unread references, eligible candidates or a stall below five; it is false after a finished, idle, not-due or `unavailable` pass, and a pass that yielded before reading its scan carries the previous value. Optional `stalledPasses` and `stallCause` (`inventory_changed` or `event_head_changed`) count consecutive passes that removed nothing because the inventory never held still or the event head moved; they carry across passes until one removes or finishes. It is null unless `status` is `unavailable`, except `unstable_reference`, which comes with `yielded`. `bound_exceeded` means a finite collector bound stopped the pass. A reference failure names the path that stopped it in the optional `reference`, relative to the repository ([ADR-0658](../../../decisions/operations/storage/0658-name-what-stops-cas-retention-and-tombstone-what-it-prunes.md)). `failed` means any other stop. `lervo application attention` reports every `unavailable` outcome and `unstable_reference` as the lifecycle issue `cas_retention_<failure>`, with a remediation. It also reports `cas_retention_stale` for an observation more than three days old, and `cas_retention_stalled` after five consecutive stalls. The worker records a pass that throws past its own handling as `unavailable`. Counts describe completed unlinks in that invocation. `unavailable` can follow partial reclamation; it means remaining work stopped without authorizing further deletion. A process crash can omit the observation. No absolute paths, hashes, private text, provider output, credentials or unrestricted errors enter this status or a new event.

The reference walk skips FIFOs and sockets, such as the event channel's, because they hold no bytes. A file that changes while it is read is read again from its new identity after 50, 100 and 200 ms, up to three times in one cycle. When the final inventory comparison finds changed, new, vanished or unread files, the pass rereads only those and compares again, for at most five rounds with the same doubling backoff, and deletes only after a round whose listing matches every completely read identity. Before each unlink, the pass durably writes a tombstone at `<cas>/tombstones/sha256/<2>/<62>` holding `schemaVersion`, `prunedAt`, `size` and `policy`. The pass checks the event head and object identity again after the tombstone and withdraws it if either moved. The CAS then reports that object as `pruned`, which convergence reads treat as absent and evidence reads as unverifiable. A completed pass removes tombstones older than 90 days.

## Read-only plan

`lervo state cas-retention --plan [--root <path>] [--json]` applies this policy to one full scan of a read-only store. It takes no lock and writes nothing. It reports CAS totals, candidates past grace, retained objects and collectable objects by reason: `unreferenced`, `event_writer_backup`, `assignment_input`, `backup_and_assignment_input`, `stage_result_superseded`, `failure_superseded` or `observation_superseded`. `status` is `planned` or `unavailable`, with `failure` set to `reference_changed`, `bound_exceeded` or `failed`. The plan names no path, hash or body and ignores the per-slice deletion bounds.

## Growth at the source

Baseline sources and stage source capture remain embedded to preserve current input identities and receipt proofs. A future version may store one immutable baseline per obligation and one capture per source snapshot, with a typed input envelope that binds their hashes. Readers must hydrate and verify every referenced object before reconstructing the exact current proof input. This change requires compatibility tests for old envelopes and crash recovery; it is outside this retention delivery.
