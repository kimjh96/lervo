# CLI bundle metafile and release evidence

## Metafile evidence boundary

The existing build description says only the `apps/cli/src/bin.ts` build in `apps/cli/scripts/build-bundle.mjs` enables `metafile: true` and retains its result. It describes writing `dist/bin.metafile.json` after normalization and the Node-runtime permission change, using two-space JSON indentation and a trailing newline, with no secondary-executable metafile or inventory merge.

The build owner was not supplied for this assessment. These script-order, formatting and metafile assertions remain unverified. A primary-entrypoint metafile alone cannot establish the complete dependency inventory of the terminal hook, packaged Node runtime or shared runtime.

## Current archive and inventory contract

[ADR-0502](../../decisions/distribution/0502-bind-native-sync-assets-to-standalone-runtime-distributions.md) requires CLI npm archives to carry both native pairs on every platform: `cas-io-darwin.node`, `cas-io.json`, `file-sync-darwin.node` and `file-sync.json`. The original native-only schema-7 archive contains nine files. Schemas 5 and 6 retain their original inventories; a seven-file legacy description must not be used as the current archive contract.

CLI release schema 9 adds the complete internal runtime inventory at `dist/repository-runtime.json`. Its canonical manifest binds sorted code-member names, sizes and SHA-256 hashes. Current selected-validator composition includes `repository-runtime.js` and the private `repository-runtime-validators.cjs` fallback. Archive validation must compare exact expanded membership and canonical manifest bytes, including independently required native assets. Package patterns or a fixed historical file count do not establish current membership.

CLI SBOM generator version 5 binds the internal runtime inventory as one component, separate from native assets. ADR-0502 retains generator version 2 for schema 6 and version 1 for schema 5. The earlier guide described schema-5 inventory as `pnpm-lock-and-esbuild-metafile` and schema-6 inventory as `pnpm-lock-esbuild-metafile-and-native-archive`, with two native files and explicit application dependency edges. Those literal generator descriptions require their implementation or generated artifacts for verification and do not describe the current complete four-file native contract.

[ADR-0503](../../decisions/execution/verification/0503-compile-schema-validators-at-build-time.md) also requires a bounded `runtimeDependencies` inventory derived from generated validator bundle inputs. Release snapshot and SBOM owners combine it with outer bundle inputs so embedded runtime helpers retain package identities. Dependency completeness requires checking these owners, the lock graph, all relevant bundle inputs and exact component relationships.

## What this assessment establishes

No release manifest, CycloneDX document, archive, captured package README or computed source facts were supplied. The previous statement that a supplied release manifest listed executable archive hashes is therefore unsupported. The requirements above establish the expected contract, not an observed current archive count, matching hashes, dependency completeness or packed README claims.

Build configuration and recorded manifest or SBOM values do not prove a successful build, matching generated bytes, completed platform smoke tests, signed provenance, or publication. The manifest and SBOM retain their owning update and verification commands under [ADR-0086](../../decisions/release/packaging/0086-canonical-cli-release-artifact-manifest.md) and [ADR-0092](../../decisions/release/assurance/0092-cli-release-sbom.md). Actual-artifact acceptance requires those exact inputs and verification results.
