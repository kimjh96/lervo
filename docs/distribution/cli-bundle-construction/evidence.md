# CLI bundle metafile and release evidence

Only the `apps/cli/src/bin.ts` build in `apps/cli/scripts/build-bundle.mjs` enables `metafile: true` and retains its result. After normalization and the Node-runtime permission change, the script writes that result to `dist/bin.metafile.json` as JSON with two-space indentation and a trailing newline. It emits no metafile for the terminal hook or packaged Node runtime and performs no inventory merge across builds.

The supplied release manifest lists all three executables and their archive hashes, but its bundle entry and output identify the primary CLI executable. The SBOM identifies its inventory source as `pnpm-lock-and-esbuild-metafile`. The single emitted metafile does not independently establish a complete inventory of dependencies unique to either secondary executable. Establishing completeness requires inspecting the inventory generators and secondary-entrypoint dependency evidence.

Build configuration and recorded manifest or SBOM values do not prove a successful build, matching generated bytes, completed platform smoke tests, signed provenance, or publication. The manifest and SBOM retain their owning update and verification commands under [ADR-0086](../../decisions/release/packaging/0086-canonical-cli-release-artifact-manifest.md) and [ADR-0092](../../decisions/release/assurance/0092-cli-release-sbom.md).
