# CLI build guide: supported requirements and withdrawn implementation claims

Status: `documentary_correction; implementation_verification_pending`

This amendment governs the evidence interpretation of [CLI bundle build configuration and execution](build.md). It preserves that document's bytes while withdrawing its unsupported implementation descriptions from current build guidance. Its opening qualification does not make the later present-tense descriptions verified facts.

## Claims withdrawn from current guidance

The supplied assessment contains no build script, CLI package manifest, build helper or generated output. Consequently, the following descriptions in the build guide remain unverified and must not be used as an account of the current implementation:

- Root resolution, recursive directory creation and build working directory.
- Registration of `lervo` and `lervo-node`, the exact source-to-output table, and the assertion that both commands import the same implementation module.
- Exact esbuild target, format, resolution order, logging, legal-comment settings, banners and plugin registration at each entrypoint.
- UTF-8 literal emission and its asserted size rationale.
- The number and targets of normalization calls, their concurrency and ordering, permission changes and the absence of other permission changes.
- Output retention, local exception handling, rollback and cleanup behavior.
- Metafile emission details and its ordering relative to native copying.
- Helper exports, application entry functions and absence of command or service effects on import.

This withdrawal does not assert that these descriptions are false. It removes their status as current implementation guidance until the corresponding owners and outputs are inspected. The [metafile evidence record](evidence.md) independently identifies the same missing build-owner evidence.

## Requirements supported by the supplied decisions

[ADR-0503](../../decisions/execution/verification/0503-compile-schema-validators-at-build-time.md) requires current generated validators before bundling, preserves validation and error contracts, and assigns the four generated files to the schema compiler. It requires twelve selected validators and a complete synchronous CJS fallback for the internal shared CLI/Node runtime, with the private coordinate-parser substitution confined to its declared importer boundary. Ordinary package, Hub and terminal consumers retain the complete map. Terminal minification preserves the unchanged 8 MiB bound. These are requirements, not proof of a particular esbuild invocation or generated byte sequence.

[ADR-0215](../../decisions/release/packaging/0215-supported-runtime-release-portability.md) requires SQLite compatibility, external consumer-selected Claude SDK packages in the provider-invoking entrypoints, normalized generated executable text and portable release bytes. It does not establish the build guide's normalization call count, call order, permission operations or exact banner text.

[ADR-0502](../../decisions/distribution/0502-bind-native-sync-assets-to-standalone-runtime-distributions.md) requires both native pairs in current CLI archives and a complete bounded internal runtime inventory. CLI release schema 9, Node schema 5 and CLI SBOM generator version 5 bind the aggregate runtime separately from native assets. Private captured-buffer publication, conflict preservation and manifest-last installation are contractual requirements. They do not prove that an observed build or installation satisfied them.

## Verification still required

Restoring an implementation claim requires the exact package manifest, build owner and relevant helper implementations. Generated validator manifests, bundle outputs, runtime inventories and relevant build metadata must establish the resulting bytes and membership. Command registration requires package metadata; import-effect and export claims require the helper and composed modules. Cleanup, permissions and ordering require their actual implementation and, where claimed as execution results, corresponding observations.

No such implementation or output verification was performed by this documentary correction. It establishes no successful build, packed smoke, platform qualification, deployment or publication. Original source prose remains preserved, but this amendment controls its use as current guidance.
