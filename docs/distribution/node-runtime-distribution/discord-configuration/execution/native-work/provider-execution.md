# Provider execution and continuity

`command.provider` selects Codex or Claude for native repository work. Matching `remoteCommands.providerHost.executables`, `models`, and `reasoningEfforts` values configure the selected CLI. Optional `routing.workTimeoutMs` limits a turn to 10 seconds–30 minutes; the default is 30 minutes. The provider receives an exact finalization-start time with a bounded reserve and must checkpoint after its first material edit. Reaching the hard deadline is `provider_turn_timeout` even when a CLI exits zero or emitted intermediate prose; intermediate commentary is never accepted as a completed result.

When a provider returns a successful result with observed changed paths but leaves the unchanged baseline workstream revision, the Node may record one host recovery checkpoint on that same active or blocked workstream before completion verification. This does not make the provider CLI optional for crash safety: no host checkpoint is created for a missing, switched, completed, or cancelled workstream or for a provider turn that did not return a successful final result.

Optional `remoteCommands.providerHost.executionProfiles` enables semantic allocation. It must define `routine`, `reasoning`, and `review`. Each profile declares a `preferredProvider` and a `providers` map whose routes contain an optional model, required reasoning effort, and optional `timeoutMs` from 10 through 300,000 milliseconds. Routine requires `low` or `medium`; reasoning and review require `high`, `xhigh`, or `max`. The selected route's timeout applies to managed conversation work as well as provider transport, so slower high-effort review is not constrained by the routine response budget. When Codex and Claude are both allowlisted, reasoning and review must prefer different providers. This lets routine work use a balanced route while design, judgment, and review use higher-quality routes without concentrating every new turn on Codex.

The preferred provider applies to each new unbound source event, including independent review after work on another provider. Provider-specific sessions remain separate and resumable; only an explicitly provider-bound named agent overrides the profile preference. A replayed source event keeps its originally admitted provider. Without a semantic profile, the most recent provider session retains the legacy continuity behavior. Missing matching routes fail closed. Completion telemetry records the profile and allocation reason alongside the exact requested model and effort.

The installed PO fleet's reviewed model policy is [versioned separately](../../../../../../scripts/distribution/po-model-policy.json) from agent identity and repository authority. `reconcile-po-model-configs.mjs` dry-runs each exact Node configuration, then applies the same policy only with an explicit owner-only backup directory. Ordinary work uses a strong medium-effort route; design and consequential judgment use high effort; independent review prefers the other provider. The conversation response model remains separately configured. Check installed provider availability, exact requested routes, and observed usage before claiming that a rollout changed live execution.

A completed conversation or thread resumes the opaque session for that hired agent and selected provider. Exact duplicate requests coalesce while active and reuse the recent result instead of running twice.

Replaying a running source event, including after the database reopens, retains the original attempt without starting another provider process. Its acknowledgement confirms duplicate suppression, not that the earlier process is still alive. Admission and replay inspection share one SQLite transaction. Conflicting identities or content are rejected without changing the original turn.

The runtime prepends its Node executable directory to the provider process `PATH`, allowing an absolute Codex launcher using `#!/usr/bin/env node` to run under a minimal systemd environment. Codex receives the exact Git common directory as an additional repository-owned writable root so `.git` sandbox protection does not block Lervo workstream bookkeeping.

Provider version preflight applies the same Node-directory `PATH` rule but exposes only `PATH` to the probe. Without this rule, a valid stored login can pass while the version probe incorrectly reports `probe_failed` for an `env node` launcher, preventing supervised owner decisions from starting. The login probe and actual provider process retain separate environment contracts.

A message-scoped provider or dispatch failure follows the durable interaction failure path without stopping other configured Discord identities.

Before activating a Node distribution that changes native provider arguments, run a bounded, no-session-persistence print-mode smoke check against each configured provider executable and output format. Claude `--print --output-format stream-json` also requires `--verbose`; a version or login probe alone does not validate this execution contract.
