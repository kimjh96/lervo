# Execution and evidence boundaries

Native work may inspect and change repository bytes. Its execution instructions prohibit commits, pushes, deployment, broad deletion, and secret disclosure for ordinary requesters. An authenticated human or configured effect requester may explicitly request one commit, push, remote creation, or exact-target deployment. A deployment requires a rollback, current runtime and authority checks, and installed verification; it grants no risk-limit increase, kill-switch reset, or credential change. These are policy instructions, not guarantees enforced by an operating-system sandbox.

Results report paths that Git observes as changed without claiming exact-path verification by a managed run. Native work never uses fixed queue text.
