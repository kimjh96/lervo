# CLI bundle construction and inventory scope

`apps/cli/scripts/build-bundle.mjs` builds the CLI package's three JavaScript executables. It resolves the CLI and repository roots from its location, recursively creates the CLI `dist` directory, and runs three sequential esbuild builds with the repository as the working directory.

| Source entrypoint | CLI package output |
| --- | --- |
| `apps/cli/src/bin.ts` | `dist/bin.js` |
| `apps/cli/src/terminal-hook-bin.ts` | `dist/terminal-hook.js` |
| `apps/node-runtime/src/bin.ts` | `dist/node-runtime.js` |

All three builds bundle for Node with target `node22.13`, emit ESM, prefer `module` before `main`, omit legal comments, and use silent esbuild logging. Each adds a banner creating a local `require` through `node:module`'s `createRequire(import.meta.url)` and registers `nodeSqliteBundlePlugin`. The plugin's internal behavior is outside this script's evidence.

The CLI and packaged Node-runtime builds explicitly keep `@anthropic-ai/claude-agent-sdk` external. The terminal-hook build supplies no explicit external-package list; this alone does not establish which dependencies it imports. [ADR-0215](../decisions/release/packaging/0215-supported-runtime-release-portability.md) defines consumer-platform selection and SQLite compatibility contracts.

After all builds complete, the script concurrently calls `normalizeGeneratedTextFile` for each executable and awaits all three calls. It then sets `dist/node-runtime.js` to mode `0755`; it contains no corresponding chmod for the other executables. The normalization helper's implementation and resulting bytes require separate verification.

## Metafile and release evidence

Only the `apps/cli/src/bin.ts` build enables `metafile: true` and retains its result. After normalization and the Node-runtime permission change, the script writes that result to `dist/bin.metafile.json` as JSON with two-space indentation and a trailing newline. It emits no metafile for the terminal hook or packaged Node runtime and performs no inventory merge across builds.

The supplied release manifest lists all three executables and their archive hashes, but its bundle entry and output identify the primary CLI executable. The SBOM identifies its inventory source as `pnpm-lock-and-esbuild-metafile`. The single emitted metafile therefore does not independently establish a complete inventory of dependencies unique to either secondary executable. Establishing completeness requires inspecting the inventory generators and secondary-entrypoint dependency evidence.

The script does not clean the output directory before building and has no local catch or rollback. A rejected build or subsequent awaited filesystem operation stops further execution; earlier outputs can remain.

Build configuration and recorded manifest or SBOM values do not prove a successful build, matching generated bytes, completed platform smoke tests, signed provenance, or publication. The manifest and SBOM retain their owning update and verification commands under [ADR-0086](../decisions/release/packaging/0086-canonical-cli-release-artifact-manifest.md) and [ADR-0092](../decisions/release/assurance/0092-cli-release-sbom.md).
