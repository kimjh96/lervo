# Boundaries, evidence, and compatibility

## Ownership boundaries

`application-contract` owns requests/reports; `work-controller` owns pure next-action and plan validation. Workforce owns identity, bindings, leases, and atomic transitions. Policy/resource contracts own authority and budgets. Applications compose storage, timers, and provider execution. Host adapters translate requests and render results; providers execute admitted work. Core types contain no product or agent names.

## Evidence boundaries

Link the user request to conversation, native execution, workers, retries, and verification. Separate requested model/effort from provider-observed identity and usage. Deduplicate cumulative tokens and mark missing scopes unobserved. Retrieval records identify the engine and stage; supplementary v1 ranking cannot be described as the v2 primary retriever. Partial observations never become a whole-request bill.

## Compatibility and activation

Additive schemas and protocol capabilities require compatible readers before writer activation. Preserve manual workflows. Existing assignments acquire supervision only through exact owner binding; migration never starts historical queued work. Activation requires mandate installation, role validation, readiness and recovery checks, and installed acceptance. This documentation change activates none of them.
