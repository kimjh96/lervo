# Managed native owner reasoning

The explicit Node factory can supply an owner proposal path when the host omits application planning/effect ports and configures native owner reasoning. It reads the canonical goal, mandate, registered staff and roles, responsibilities, current task artifacts, required instructions and bounded retrieved sources, storing exact context in CAS. Source text and results stay outside operational event fields.

## Context and evidence

`staleResponsibilities` contains non-terminal assignments whose current binding predates the goal revision, including executor, bound and current revisions, lease expiry and whether an attempt started. The owner escalates while such a lease is live and revises the assignment once the lease expires or is absent. Meanwhile, the Node refuses preparation or dispatch.

`recoveryObservations` contains canonical `work.supervision.readiness.failed` records—safe non-starts recorded before any worker process—and exact `assignment.lease.renewed` records for current assignments. These let the owner judge goals naming permission repair or a renewed-lease run from recorded facts instead of escalating for missing evidence. Their absence never implies a repair.

For a Discord-bound goal, context distinguishes the outbound product-owner speaker from the requester. A separate read-only check of durable native ingress supplies human provenance only when its event ID, content, target and policy match the bound request. Ordinary `message.created` intake also requires immutable medium- or high-confidence `supervision_goal_request` intent evidence. Historical `goal.requested` provenance retains its owner-mention check. Absent or conflicting evidence cannot satisfy a human-intake criterion.

## Composition boundaries

Canonical workspace preparation, dispatch, scoped hiring, unstarted reassignment and amendment, rejected-result rework, and contextual publication are composed. Explicit [installed startup configuration](node-composition/installed-startup.md) connects the factory to Node lifecycle. Safe worker-failure recovery, scoped handoffs, research verification, installed journeys and reviewed activation still require their own implementation and evidence.

The owner may supply an independent semantic writing verdict for [assignment completion](managed-execution/assignment-completion.md). The exact native result and repository writing policy remain bound to the resulting permit; task acceptance follows separately.

A `hire_worker` judgement can prepare [one scoped child hire](worker-hiring.md) only after actual staffing and provider observations establish a gap. Hiring remains separate from assignment, provider execution and external deployment.
