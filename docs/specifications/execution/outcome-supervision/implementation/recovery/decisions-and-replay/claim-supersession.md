# Responsibility claim supersession

A `revise_responsibility` decision whose `work.responsibility_claim.v1` effect failed before any write leaves its decision pending. Its exact acquisition is fenced and atomic, so failure before the transaction proves absence of the binding: no `work.responsibility.bound` event exists for the claim's deterministic binding identity and the assignment record still matches the claim's expected hash.

The Node supersedes such a claim only when its source changed or its plan deadline passed, under the current owner fence and installed authority, with an unchanged event head at the fenced transition. The version-7 `work.effect_absence` inspection contains exactly `schemaVersion`, `kind`, `effectContract`, `decisionId`, `planHash`, `effectHash`, `sourceRevisionDigest`, `assignmentId`, `assignmentSourceHash`, `bindingEventAbsent`, `eventHeadHash`, `observedAt`, and `invalidatedBy` (`source_changed` or `deadline_expired`). It records the existing envelope-version-3 `work.supervision.decision.superseded` event; no new event type, prose, path, or credential is introduced. The decision journal validates the inspection with the same rules before treating the decision as superseded.

Without this path an unbound claim kept every later cycle in `pending_decision_requires_reconciliation` although nothing had happened. Supersession proves only that the claim never bound; it does not release a lease, prove a worker did not start, or admit a later claim. After supersession the owner decides again over the current source, and a successor responsibility whose completion window can no longer hold a bounded lease yields no automatic claim, so the owner must propose a new responsibility or escalate.
