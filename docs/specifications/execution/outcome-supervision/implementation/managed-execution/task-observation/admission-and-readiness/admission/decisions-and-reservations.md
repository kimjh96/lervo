# Decisions and reservations

The current decision is excluded from its own source digest and reservation charge. Other decisions invalidate the task snapshot. Terminal events alone do not prove zero usage.

Unscoped aggregate admission is blocked by an unresolved prior invocation or a missing, partial or incomparable accounting group. Unknown effect contracts retain an unavailable reservation total. A reservation does not prove that a provider cannot exceed its estimate.

The sole exception to a missing usage receipt is a run with an exact canonical `interrupted_before_turn` failure and readable boot-transition diagnostic. The complete pre-turn prefix and host fence prove that no managed model turn started. The observer removes only that run from the required provider-usage population and settles its outstanding reservation. It does not write a synthetic zero-token usage event or omit any started run. A bare reboot or terminal event without its matching diagnostic remains blocking.

A superseded owner or managed dispatch has no outstanding reservation only after revalidation proves its historical admitted decision, exact absence envelope and matching deterministic run evidence. Managed dispatch uses the version-four empty-run or version-five exact reservation-only envelope described in [worker execution](../../../worker.md).

A supersession event alone cannot erase usage or capacity. An event outside the envelope's exact permitted set, an altered envelope or an inconsistent binding blocks the exemption. Recorded provider usage and partial attempts remain accounted.
