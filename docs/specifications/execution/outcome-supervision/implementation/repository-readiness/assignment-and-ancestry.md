# Assignment and ancestry

The assignment must exist at the responsibility's exact revision, project, workstream, role version, and contract hash, with matching acceptance criteria. The existing assignment execution-authority API verifies the active assignee, exact current unexpired lease, allowed provider, plan paths, and complete verification-suite set. The task's responsibility hash remains bound to the reviewed action plan.

The adapter resolves current worker ancestry and role contracts, including the bounded delegation chain, active lifecycle, project identity, provider restrictions, capability ceilings, and responsibility paths. Every ancestor must admit the plan's scope. A role capability requiring approval does not prove approval was granted; application admission supplies that decision.

After workspace inspection, the probe rereads assignment and ancestry. Changed records, missing sources, or an observation lasting over five seconds invalidate the result. Lease renewal changes assignment revision and requires an updated responsibility and plan. The probe neither reclaims a lease nor manufactures a responsibility binding event.
