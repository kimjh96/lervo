# Repository readiness observations

After binding application readiness, Node dispatch, retry, and owner execution independently inspect canonical workforce records and the registered Git worker workspace. Positive application evidence cannot bypass these observations. Allocation without execution does not run the probes.

The probes cover [assignment and ancestry](repository-readiness/assignment-and-ancestry.md), the [Git workspace](repository-readiness/git-workspace.md), and [evidence and validation](repository-readiness/evidence-and-validation.md).

Before repository probes, Node loads the [canonical responsibility artifact and binding history](storage/responsibilities.md), then compares available fields with the canonical assignment and exact reviewed plan. Node also adds [configured executable observations](runtime-readiness.md) and [control-repository knowledge inspections](knowledge-readiness.md).

Provider authentication, task-tool permissions, actual knowledge delivery, research source policy, verification, and budget observations remain application responsibilities. Production responsibility installation, startup, external effect adapters, and autonomous execution remain unactivated.
