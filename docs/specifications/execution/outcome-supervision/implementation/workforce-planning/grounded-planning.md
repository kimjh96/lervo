# Grounded planning

## Repository evidence

Node planning combines repository search, exact source loading, and canonical workforce observations. It requires the current active workstream ID and revision, reads applicable instruction files and the product README when present, uses the configured managed search path, and checks selected document bytes against recommendation hashes. It rejects unresolved source paths, conflicting recommendation hashes, changed selected bytes, a changed workstream, or loaded context exceeding 256 KiB.

Planning evidence retains search engine and attempt identity, selected recommendation IDs, loaded paths and hashes, and bounded retrieval coverage. Searches without recommendations record that limitation, not proof that prior knowledge is absent. Planning does not claim provider injection or use. Source text stays within the governed context/artifact boundary, outside operational event fields. The effect adapter must revalidate source currency before executing a plan.

## Workforce observation and selection

Workforce observation reads actual agents, assignments, role contracts, and live leases. Candidate matching checks exact role/version/hash, active ancestry, provider compatibility, capability declarations, and responsibility paths. A live worker lease or overlapping live path scope marks a candidate busy. Workforce changes during observation reject the snapshot. Unavailable roles remain unobserved, not proof that no qualified worker exists. Matching declared capabilities proves neither successful task execution nor external permission.

Selection prefers an available matching worker over owner execution; owner execution requires no minimum headcount. Busy qualified staff indicate a capacity gap; fully observed incompatible staff indicate a skill gap. Unobserved staff or an unavailable provider environment block absence-based staffing decisions.

Reassignment requires lease reconciliation, borrowing requires a scoped handoff, and hiring requires separate mandate and capacity review. The rationale records these alternatives without granting their effects.

## Provider observations and dispatch

The composed planning adapter observes the configured provider executable and explicit login profile through provider adapters. Login presence and executable availability establish only those observations. Dispatch still requires actual tool permissions, verification pins, source policy, budget, workspace, and current responsibility checks.
