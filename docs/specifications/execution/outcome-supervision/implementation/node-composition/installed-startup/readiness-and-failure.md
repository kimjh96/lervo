# Readiness and failure meaning

The optional `supervision` component in the owner-only Node health snapshot uses `pending`, `ready`, `dormant`, `attention`, `disabled`, and `unavailable`. A configured service starts pending. Observed cycles report service readiness under these rules:

- Blocked or uncertain cycles report `supervision_attention_required` with the cycle's bounded attention `reasonCodes`: at most 16 identifier codes, such as `readiness_tools_failed` or `responsibility_lease_unresolved`.
- Cycle exceptions report `supervision_cycle_failed` with one bounded `reasonCodes` entry derived from the error's code or class name. For each failed cycle, the service writes one error-stream line naming that code, the error class, and the first 200 characters of its message.
- `supervision_workstream_inactive` reports `dormant` with required `reasonCode: workstream_inactive`. It means no exact canonical workstream or no exact bound request origin is available for the reviewed binding; another workstream being selected in `current.json` is not sufficient cause once [bound-workstream supervision](../../../../../../decisions/execution/orchestration/governed-work/workstream-concurrency/0423-parallel-bound-workstreams.md) is installed. The owner does no supervised work while dormant. It is not a failed cycle and emits no failure log. A later exact request binding or eligible lineage binding returns the component to pending and a successful cycle returns it to ready. Other authority, source, or execution errors remain unavailable.
- A V3 goal whose next exact token reservation no longer fits reports `attention` with required
  `reasonCode: goal_budget_insufficient` and exact `resourceBudget` counters. It starts no new
  supervised effect, but conversation, synchronization, remote control, and the Node process remain
  operationally ready. Legacy workstream-wide mandates remain unavailable on the old
  `aggregate_budget_exceeded` reason rather than being mislabeled as goal-scoped.
- A V3 mandate with reviewed `aggregateTokenPolicy.mode: per_attempt_only` never reports a
  cumulative budget state. Historical aggregate usage is not an admission boundary; the exact
  attempt, retry, concurrency, capacity, deadline, expiry, provider, role, capability, and path
  checks remain mandatory.
- Publication is required only when the verified bound request or trusted result configuration supplies an origin. Installing a conversation adapter alone does not require publication. A completed local goal with `accepted_local_result_available` and no next action reports `dormant` with required `reasonCode: local_result_canonical`. Its accepted result stays canonical in the repository. Malformed or missing canonical request evidence still fails closed; this rule does not claim delivery.
- An effect that failed after invocation reports `effect_outcome_uncertain` plus the adapter's bounded failure code, if present. The managed worker boundary distinguishes `managed_output_bound_exceeded`, `managed_revalidation_failed`, `managed_deadline_elapsed`, `managed_cancelled`, `managed_stdin_failed`, `managed_launch_failed`, `managed_process_failed`, `managed_dispatch_evidence_missing`, and `managed_outcome_unreconciled`. None includes child output.

These observations describe runtime operation, not accepted task completion or delivered user results. Aggregate health remains starting while supervision is pending and degraded when it is unavailable. A dormant or goal-budget-attention supervisor does not hold the otherwise operational Node in starting: aggregate health can be ready, but the explicit supervision component remains visible and must never be presented as an active supervised goal. Fleet status exposes both conversation and supervision components so the aggregate cannot conceal that distinction.

A previously bound active goal receives at most sixty seconds of startup grace, with an explicit timer wakeup even without a new source event. Unfinished leased duties and pending decisions retain immediate continuation. Before evaluation, grace-period idleness reports pending.

An idle or busy cycle without a fresh report preserves the preceding health observation. It cannot clear an unavailable state merely because no owner observation ran.

Health retains only bounded status, failure, and reason codes. The dormant state is a replaceable health projection, not a new durable event; its required reason is a fixed identifier and carries no workstream or agent ID. It excludes task prose, prompts, source bodies, credentials, transport addresses, and provider errors. Failure to persist runtime health resolves the service failure signal, causing Node shutdown with `supervision_runtime_failed`. An ordinary task or effect failure remains available for the existing bounded recovery loop. Transport health does not replace supervision health.

Bound-workstream selection reads the latest exact snapshot event and content-addressed artifact for the mandate's workstream ID. It verifies contiguous locally recorded revisions, allowing only an exact, artifact-verified `hub_replication_import` checkpoint to bridge revisions that Hub replication did not transfer, and checks the selected projection when that workstream is selected. Completion and standing succession of an unselected goal append their own snapshot event without replacing another workstream's selected projection or pending approval. A missing artifact, forked chain, unexplained gap, stale predecessor, changed mandate, or shared workforce conflict fails before the effect. The snapshot event keeps its existing bounded IDs, hashes, revision, status, and timestamp; no new event type, credential field, or Discord message body is introduced. Local tests do not by themselves prove installed parallel operation or clear a conversation deployment approval.

Configuration, startup, local failure handling, health aggregation, and existing runtime regression tests cover this composition. Positive installed operation, reviewed activation, natural Discord intake, and the complete acceptance journeys remain separate evidence requirements.
