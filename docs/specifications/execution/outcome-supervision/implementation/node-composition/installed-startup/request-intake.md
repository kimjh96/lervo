# Installed supervision request intake

An active installed owner can bind one request to its current workstream through local stdin or its configured Discord speaker. Both use the same Node intake under the exclusive owner lease. Admission identifies the current installed goal; it does not imply creation of an unrelated goal.

## Startup and request triggers

Installation alone is not a request trigger. A configured owner without an exact `work.supervision.bound` origin remains dormant and performs no reasoning or effect.

When a process starts with an older origin already bound, its first observation records only a source cursor. Startup, a mandate revision, and removal of a cumulative budget block are not fresh instructions. An unresolved recorded decision is still reconciled before this deferral.

A leased or dispatched assignment without a terminal event is an unfinished durable duty. After restart, it resumes through ordinary admission, readiness, and recovery checks. This is neither a new request nor permission to repeat a confirmed effect.

A later canonical source change wakes the ordinary owner loop for otherwise deferred work. A request newly bound after process start runs without an extra synthetic trigger.

The origin check precedes the owner lease, peer refresh, pending result delivery, recovery, reasoning, and effect preparation.
