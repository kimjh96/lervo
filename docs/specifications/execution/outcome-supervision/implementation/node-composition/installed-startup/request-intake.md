# Installed supervision request intake

An active installed owner can bind one request to its current workstream through local stdin or its configured Discord speaker. Both use the same Node intake under the exclusive owner lease. Admission identifies the current installed goal; it does not imply creation of an unrelated goal.

Installation alone is not a request trigger. A configured owner with no exact
`work.supervision.bound` origin remains dormant and performs no reasoning or effect. When a process
starts with an older origin already bound, its first observation records only a source cursor; it
does not reinterpret startup, a mandate revision, or removal of a cumulative budget block as a
fresh instruction. An unresolved recorded decision is still reconciled before this deferral. A
later canonical source change wakes the ordinary owner loop, while a newly bound request after
process start runs without an extra synthetic trigger. The origin check precedes the owner lease,
peer refresh, pending result delivery, recovery, reasoning, and effect preparation.
