# Validation boundaries

Configuration, startup, local failure handling, health aggregation, and existing runtime regression tests cover this composition. Positive installed operation, reviewed activation, natural Discord intake, and complete acceptance journeys remain separate evidence requirements.

The supplied health-test definitions assert goal-budget versus legacy-budget health, typed inactive-workstream handling, bounded reason codes, newline normalization, bundle-coordinate extraction, recovery-evidence diagnostic formatting, and wrapped effect causes.

The startup-recovery test mocks the runtime and drives its hooks to check pending health, busy-cycle retention, idle recovery, and persistent ordinary attention.

These definitions do not establish a passing test run, general diagnostic redaction, successful installed authority reads, or installed acceptance.

[Bound-workstream selection and evidence](bound-workstream-selection.md) defines snapshot verification and the limits of local test evidence.
