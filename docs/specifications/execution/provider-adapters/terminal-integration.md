# Direct Terminal Integration

Terminal profiles merge Lervo handlers into project arrays, preserving settings and hooks. Handlers resolve the Git root from the provider working directory and invoke the tracked launcher through Node, never a PATH-resolved global `lervo`. [ADR-0539](../../../decisions/execution/providers/hooks/0539-keep-the-terminal-hook-runtime-host-local-behind-a-tracked-launcher.md) keeps that launcher at `.lervo/generated/terminal-hooks/runtime-v2.mjs`, bounded at 16 KiB, with a schema-4 manifest binding its exact bytes. The launcher verifies the host-local runtime and declared assets before importing the runtime in the same process and before reading hook input. Two paths read the input without importing the runtime: a hook the [resident context server](../stage-observation-and-performance/compact-terminal-context/resident-context-socket.md) serves, and a prompt answered from that server's cached base ([ADR-0645](../../../decisions/execution/providers/hooks/0645-answer-an-unserved-prompt-from-the-cached-base.md)). Neither runs this process's runtime, so a damaged runtime is reported by the next hook that imports it. Provider commands, Windows commands, and the contract `lervo_terminal_hooks_v2` remain unchanged.

Legacy contract-v1 handlers migrate in place. Generated-only reconciliation replaces legacy repository bundles with the launcher and removes generated native assets through the existing rollback journal. CLI runtime upgrades publish host-local bytes; the tracked launcher changes only with its contract. Installed interactive startup and explicit knowledge migration may publish; residents repair missing, invalid, marked, or interrupted state without replacing another live publisher's valid runtime. An installed CLI never publishes, or repairs, over a runtime whose publisher is the host's active install, the one its `lervo` link runs, when that install is a newer `@lervo/cli`: an older install that something still runs, such as a Stop's worker bound before the upgrade, would otherwise put its older runtime and launcher back. After a rollback the newer install is no longer active, so the active older CLI publishes and repairs its own runtime again. A publisher that is not active, gone, or unreadable, or a host whose `lervo` link is not in its default bin directory, leaves publishing as before. Missing runtime state preserves unmanaged availability; integrity failures remain fail-closed under ADR-0539.

Reconciliation plan IDs bind the exact target bytes and latest canonical terminal-application event ID, allowing an old-to-new transition to recur safely after an intervening version without colliding with earlier recovery evidence. A changed application-event coordinate makes the plan stale. Under [ADR-0561](../../../decisions/foundation/0561-decide-without-the-owner-cross-check-reversible-effect-notice.md), user-owned provider configuration changes take no approval: apply backs up the provider hook files to `.lervo/data/backups/`, applies the exact plan, and verifies that the integration inspects as current. A failed verification, or an apply that fails part-way, restores the backup; a failed verification fails with `terminal_integration_verification_failed` and holds that exact plan, so `lervo upgrade` reports it as `lervo_debt` (`verification_failed`) until the plan changes. `lervo state restore <backup-id>` undoes an applied change and holds the provider hook merge as the owner's choice (`owner_restored`) until `lervo repository release`.

Invalid JSON or shapes, conflicting Lervo commands, Claude disablement, or Codex project-hook disablement blocks migration. Authority excludes local, global, and organization settings.

Successful apply is installation evidence, not activation readiness. Human and JSON output must immediately disclose Codex's one-time `/hooks` review. `terminal status` remains `action_required` until canonical contract-v2 invocations for both events are observed, distinguishing an unreviewed or unobserved Codex hook from a stale repository lifecycle.

[Native skill observation](native-skill-observation.md) defines transcript positions, resident parsing, invocation events, and the daily retirement review projection. Hooks record coordinates and hash at most the first 4 KiB of the transcript for authenticity; they never parse transcript entries. The resident running through the full CLI owns parsing. Detached worker launch requires the recorded CLI entry's real path, ownership, safe permissions, and exact SHA-256 binding. Invocation observations do not prove instruction compliance, managed delivery, retirement review, or removal.
