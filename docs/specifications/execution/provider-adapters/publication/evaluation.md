# Evaluation and Result Projection

Managed runs use a role-bound English machine-result protocol. A separate read-only session of the selected local provider evaluates human-facing publication in an empty temporary repository without documents, tools, or write access. Its exact JSON is content-bound evidence, not independent cross-provider or human review, proof of understanding, or writing-policy E3. Failure blocks publication and CLI success, but not an already verified file change.

A human-facing repository role receives the repository language contract as an exact Lervo-generated E3 document bound through its `writing.policy` rule. The role, session, envelope, document bytes, and content hash must agree before provider execution. Machine-facing roles retain a null writing-policy binding. This delivery is distinct from the later publication evaluator and does not make its result independent review.

The validated result is the E4 source. Both adapters carry the same provider-neutral evidence-token instruction. The runtime does not post-filter matching tokens against task ground truth.

Before publication, remove only exact evidence tokens for current E3 versions and store the human artifact under a separate digest. Writing checks, permits, `run.completed`, and display bind to that projection. `adapter.result.captured` retains the unprojected digest without content. Unknown tokens remain visible. An empty projection fails closed.
