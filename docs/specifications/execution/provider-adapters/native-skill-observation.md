# Native terminal skill observation

[ADR-0542](../../../decisions/execution/grounding/0542-observe-native-skill-use-instead-of-repeating-skill-disclosure.md) defines this contract. Providers disclose installed skills. Compact context adds no installed-skill list. Explicit `/name` and `$name` anchors retain the ADR-0538 pointer behavior.

## Hook ingress

`transcript_path` is optional on both hook events. Invalid optional values provide no transcript coordinate. Prompt submission accepts only a regular file owned by the current user under `~/.claude/projects/` or `${CODEX_HOME:-~/.codex}/sessions/`. The resolved path must remain inside that directory. A symlinked provider root or an escaping link is unavailable. It captures the canonical path, byte size, device, inode, prefix length, and SHA-256 of at most the first 4 KiB. The open-turn marker retains this position with the existing context event and provider digests. Historical markers without transcript coordinates remain readable. Coordinates without the prefix binding cannot establish coverage. Markers are bounded at 8 KiB and expire after six hours.

Stop captures the final position and commits `terminal.turn.observed` before enqueueing the range. The queue binds the prepared context event ID, closing turn event ID, and repository HEAD at Stop. An unavailable HEAD is recorded as null. These distinguish Claude turns whose provider turn digest is null. Hooks hash the bounded prefix and never parse transcript entries. Queue failures never block Stop.

The host-private queue lives at `.lervo/state/knowledge/terminal-skills/queue/`. Files use mode 0600 in directories created with mode 0700. Producers refuse symbolic links in state directories. Records contain only provider coordinates, event IDs, transcript positions, the Stop revision, and enqueue time. They expire after 24 hours. A hook publishes one complete record atomically without replacement and performs no queue scan or cleanup. Only the resident expires records and enforces the 128-entry bound on eligible records, using the current cycle time. Future timestamps or file modification times are deferred without deletion. Overflow evicts the oldest eligible unassessed range. Lost observations never become evidence of zero use.

The generated hook contains no resident parser. Every upgrade or knowledge migration remembers the full CLI entry's real path and SHA-256 in `.lervo/state/terminal-integration/worker-entry.json`, a private 0600 file. Stop can launch a detached full-CLI cycle through that entry. Before launch, the hook requires that real path to remain a regular file owned by the current user, with no group or other write permission, and a matching SHA-256. Legacy path-only records, changed entries, and failed launches leave the queue for the resident. No environment entry bypasses this binding. No PATH-resolved CLI runs on the hook path.

## Resident assessment

Every host drains its own queue under the knowledge worker lock before provider assessment, freshness preparation, or convergence ownership checks. This observation needs no provider call, Hub, or convergence write authority. A cycle processes at most four ranges. Queue-directory changes wake the resident. The daily date also invalidates its idle fence.

The resident verifies the closing event, context event, provider, and digests before reading a range. It rechecks the provider directory, current-user ownership, inode, device, size, and original prefix digest through the open file handle. Each nonblank Claude JSONL line must carry a `sessionId` whose `sha256("claude\0" + sessionId)` equals the hook session digest. A missing or different session identity makes the entire range unavailable. It reads only `[startOffset, stopOffset)`, up to 4 MiB. Later appends and earlier turns are excluded. Malformed JSONL, missing coordinates, unreadable files, replacement files, and shrunken files produce `unavailable`. A larger range produces `truncated` with no partial invocation count. A complete authentic Claude range produces `observed`, including zero invocations, only when every invocation has known attribution. Unknown and ambiguous membership yield `unknown` coverage.

Claude records qualify only through assistant `message.content` entries with `type: tool_use`, `name: Skill`, and `input.skill`. A prospective Codex parser recognizes an explicit `response_item` function call named `Skill` with JSON arguments containing `skill`. It never infers invocation from shell commands, file reads, text mentions, or tool output. No installed Codex fixture proves invocation telemetry. Every Codex assessment remains `unknown`, including readable transcripts and synthetic Skill calls. Codex turns never satisfy retirement coverage until that format is proven.

Repository membership and hashes come from `.agents/skills/<name>/SKILL.md` at the queued Stop commit. Bounded `git ls-tree` and `git cat-file` reads never substitute working-tree bytes. Tree output is capped at 2 MiB and 8,192 entries. Catalogs have at most 1,024 names per surface, blobs at most 256 KiB, and links at most 16 traversals. An unavailable commit or an absent bare identifier yields unknown attribution, with no hash or external count. Claude attribution requires its provider surface at the Stop commit. A portable file alone cannot prove that Claude installed that identifier. Provider surfaces take precedence over portable names. A provider link supplies an alias only when its Git-resolved target is a portable repository file. A provider name that collides with a different portable target is ambiguous and produces no skill observation. This also covers external links and independent provider directories. A path outside the repository cannot establish membership. A failed or incomplete catalog produces unknown coverage. Proven external links and namespaced plugin invocations contribute only a total count. An unresolved bare name may be an uncommitted skill and remains unknown. At most 1,024 invocations are attributed per range; overflow is truncated.

Both new event types require envelope schema 7. The existing writer coordinate, fresh reader inventory, backup, and exact activation plan gate publication. Advancing the reader alone does not activate writing. Upgrades target schema 7; the resident still operates with its existing schema 4 floor. Before activation, one host-private observations projection retains at most 128 turns for 30 days and at most 2 MiB. It is never synced or promoted automatically.

After activation, each repository invocation produces `terminal.skill.observed`. A delivered explicit skill pointer produces the same event with `source: prompt_invocation`, independently of transcript availability, but only when its path and hash match the Stop catalog and provider resolution is unambiguous. Transcript invocations use `source: provider_transcript`. Required fields are `skillId`, repository-relative `path`, `contentHash`, `provider`, source, both provider digests, and `observedAt`. They prove invocation evidence, never instruction compliance or managed `skill.invoked` delivery.

The resident records `terminal.skill.turn_assessed` after the closing turn. Required fields are both provider digests, `provider`, `skillTelemetry`, `externalSkillCount`, `unknownSkillCount`, `ambiguousSkillCount`, and `observedAt`. Unknown and ambiguous identifiers never enter events or retained projections. Invocations and the assessment commit together. Identities bind the context event and invocation ordinal, so replay cannot duplicate them. Assessment time uses the closing turn's time; the event envelope records when the resident wrote it. Events contain no transcript path, external skill identifier, prompt, reply, or tool content.

## Daily usage and retirement review

One current projection at `.lervo/state/knowledge/terminal-skills/usage.json` counts each installed skill's invocation evidence in the trailing 30 days. `lervo terminal status --json` exposes it as `skillUsage`. Human status reports the observed turn count and number of retirement candidates.

A skill with no invocation in the window becomes a retirement candidate after 20 fully observed assessments. Unavailable, truncated, unknown, and all Codex turns do not satisfy that threshold. The projection retains current skill coordinates, counts, and at most 20 supporting event IDs per evidence set. Its reviewer is `principal_proxy`; it creates no owner decision or approval. Removal still requires the normal repository publication path. The current source has no autonomous principal-proxy review loop. This implementation exposes review candidates without claiming that review or removal occurred.

The usage projection merges canonical events and bounded host-private invocation observations by event ID. Only canonical Claude assessments count toward the retirement threshold. Private assessments cannot establish retirement coverage. It refreshes after each resident cycle, using the current date for expiry. Deleting it loses no canonical evidence. Deleting private observations loses that unactivated evidence; lost observations never establish zero use. No transcript bytes are retained or sent to a provider.

## Verification boundary

Focused tests cover bounded prefix hashing, forged paths, symlink escapes, ownership, inode and prefix replacement, session mismatch, worker provenance, mixed-version writer activation, concurrent enqueue, revision-bound catalogs, uncommitted skills, event ordering and replay, provider aliases, external counts, earlier and later turn exclusion, the 4 MiB bound, missing or replaced files, optional Codex paths, event redaction, queue retention, and the 30-day retirement threshold. These tests are written without execution for this task.

Installed acceptance remains open. In `axli`, capture a Claude Code turn that invokes `eli5`. Retain the installed build, prepared context event ID, closing event ID, one `terminal.skill.observed` event with its path and hash, and the assessment event. The optional installed regression reads those exact coordinates when explicitly configured. Do not retain transcript content in repository evidence.
