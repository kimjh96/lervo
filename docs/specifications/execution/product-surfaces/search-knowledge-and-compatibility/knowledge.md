# Knowledge and canonicalization

Repository files, reviewed knowledge sidecars, approved skill definitions, repository state, verification results, and durable execution events retain their existing authority. Conversation, canvas, activity, search, memory, and model-generated summaries remain candidates or projections unless an owning contract defines them as durable records.

Material learned through Discord or a future first-party surface follows this sequence:

```text
observed conversation or work
  -> source-bound candidate
  -> ownership, conflict, privacy, and verification review
  -> promote, reject, defer, or supersede
  -> canonical repository source
  -> knowledge refresh and later retrieval
```

No surface may auto-promote a repeated statement, remembered approval, agent summary, canvas draft, or search ranking. Lervo preserves the distinctions among discovery, recommendation, selection, loading, injection, reference, use, verification, and canonical promotion.
