# Lervo ADE motion

Status: `active`
As of: 2026-11-23

This specification defines how the Lervo ADE moves. It is the motion chapter of the [design system](ade-design-system.md). The owner approved these principles on 2026-11-23 after trying interactive demos of each pattern. They extend the [visual language](ade-visual-language.md) and the [performance rules](../../../foundation/ade-convention/performance.md).

The same day, the owner used the real app and found it choppy: views swapped without motion, sending work left the start screen still for seconds, replies appeared in bursts, and "Working" did not read as alive. View transitions joined the catalog, and starting work, a streaming reply, and the working status changed. The principles below include them.

## Principles

1. **Motion explains a change.** An animation shows that something appeared, left, or changed state, or where focus went. Decorative motion is not allowed.
2. **Motion is short.** Entries and leavings take 200 ms, control color changes take 120 ms, and the launch view's first frame and other exits take 100 ms. Nothing else lasts longer than 200 ms, except the working status, which loops while the work lasts.
3. **Only opacity and transform move.** Translations move at most 4 px, and scale stays between 0.98 and 1. Width, height, position, margin, padding, blur, `backdrop-filter`, shadows, and the colors of large surfaces never animate. The one exception is the working line's highlight, which moves its background across the words. Nothing morphs from one shape into another: two versions of an element never overlap.
4. **Stillness is the default.** With no agent working and no input, nothing on screen moves. The working status is the only looping animation: the working line's highlight in the open conversation and the working dot in the workspace list. Both stop when the window is hidden, when nothing is working, and under reduced motion.
5. **Work answers at once.** An action that starts work shows its result immediately, even while the work completes, and what arrives later continues it in place instead of replacing it.
6. **Motion never waits.** Input works during every animation. A new state interrupts a running animation and continues from the current value. Content never waits for an animation to finish before it appears.
7. **What stays, stays still.** An element on screen before and after a change, such as the header when the conversation mode switches or the workspace list during any change, neither fades nor moves; only what changes moves. Selecting what is already shown changes nothing. The owner asked for this on 2026-11-23, after the whole view, title included, faded on every mode switch.
8. **Live changes move; loaded content does not.** Only changes that happen while the user watches animate. History loaded by scrolling, a reopened workspace, and restored sessions appear without motion.
9. **Reduced motion means no movement.** When the OS asks for reduced motion, translations, scaling, crossfades, and the working dot's breathing all stop. Changes happen at once. Only color changes on controls remain.
10. **Every motion uses a token.** Components take durations and easing from the tokens below and never hard-code them; motion that script drives reads them from the generated `motion` module. A new pattern joins the catalog below, with a demo, before it ships. The three patterns that changed on 2026-11-23 shipped to the owner's running app as their demo.

11. **Nothing pops in or drops out.** Every element that appears fades in over `motion.duration.enter`, and every element that leaves fades out over `motion.duration.leave`, both on `motion.easing.fade`, which starts and ends slowly, so no fade pops in during its first frames or drops out in its last. A decelerating curve is wrong for a fade: it reaches half opacity in the first frame, which reads as a blink. Content that changes in one place starts halfway through the old content's leaving and keeps its edge, so nothing jumps and no blank frame shows. Views follow the same rule, and so do rows that leave a list. Two things change at once by design: focus rings, and a field's placeholder as typing starts or the field clears. The motion check rejects an arrival or a leaving on any other duration or easing, and the ESLint rule requires `Presence`, or a named row of this catalog, for every element a view shows only sometimes. On 2026-11-24 the owner asked for this after a restart's result line dropped into place; the audit then found the working dot appearing in a frame, a wait's words fading in over `change`, and the launch view leaving on the accelerating exit easing, and all three now follow it.

## Tokens

| Token                        | Value                                      | Use                                                                                                                   |
| ---------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `motion.duration.change`     | 120 ms                                     | Crossfades, reveals, and control color changes                                                                        |
| `motion.duration.enter`      | 200 ms                                     | Elements entering the screen                                                                                          |
| `motion.duration.exit`       | 100 ms                                     | Elements leaving the screen                                                                                           |
| `motion.easing.standard`     | `cubic-bezier(0.2, 0, 0, 1)`               | Movement, and control color changes                                                                                   |
| `motion.rise`                | 4 px                                       | How far an arriving element rises; no translation moves farther                                                       |
| `motion.easing.exit`         | `cubic-bezier(0.4, 0, 1, 1)`               | Exits                                                                                                                 |
| `motion.easing.fade`         | `cubic-bezier(0.33, 0, 0.67, 1)`           | Every fade in and out: it starts and ends slowly, so nothing pops in during its first frames or drops out in its last |
| `motion.breathe`             | 2,400 ms, opacity 45% to 100%, ease-in-out | The working dot in the workspace list                                                                                 |
| `motion.duration.shimmer`    | 1,800 ms, with `motion.easing.shimmer`     | One sweep of the working line's highlight                                                                             |
| `motion.duration.pace`       | 120 ms                                     | The most that streamed text trails its arrival                                                                        |
| `motion.duration.wait`       | 300 ms                                     | How long an action or an opening view waits before it says so                                                         |
| `motion.duration.waitLaunch` | 1,000 ms                                   | How long the first connection waits before the frame says so                                                          |
| `motion.duration.leave`      | 200 ms, with `motion.easing.fade`          | Content that leaves in place, settling instead of dropping at the end                                                 |
| `motion.duration.settle`     | 3,000 ms                                   | How long a line that states an unseen result stays                                                                    |

The ADE uses no springs, bounces, or overshoot.

## Performance

- Every animation runs on the compositor. A pattern that needs layout or paint work per frame does not qualify, with two bounded exceptions: the working line's highlight repaints that one line, and streamed text flowing in lays out only the streaming item, each frame while the agent works.
- Looping animations belong to the working status only. Hidden or occluded windows run none: `platform/visibility` marks the document, and `ui/motion.css` pauses every animation then.
- `ui/motion.css` defines the shared keyframes once (`lervo-arrive`, `lervo-appear`, and `lervo-leave`). Stylesheet modules name them with `global(...)` and define no copies; a keyframe used by a single primitive, such as the working line's sweep, stays in that primitive's module.
- The performance harness records frame times while each pattern plays. A pattern that drops a frame at 60 fps or creates a task longer than 50 ms fails its budget.

## Verification

- `apps/ade/scripts/check-motion.mjs` checks every interface stylesheet, and the interface tests run it. It rejects:
  - durations and easings that do not come from the motion tokens;
  - transitions of anything but opacity, transform, and control colors;
  - keyframes that animate anything but opacity and transform.
- The lint rule `lervo-ade-motion/declared-motion` checks every feature view and the app frame: an element that a view shows only sometimes sits in `Presence`, or a `motion:` comment names the row of this catalog that governs it. The interface tests check that each named row exists. A new kind of element that comes and goes therefore cannot ship without a decided motion.
- The working dot's breathing uses the `motion.easing.breathe` token, so no literal easing remains.
- Interface tests cover reduced motion: under `prefers-reduced-motion: reduce`, no element in the catalog animates.
- The performance harness covers each pattern in the catalog on the owner's Mac and in WSL.
