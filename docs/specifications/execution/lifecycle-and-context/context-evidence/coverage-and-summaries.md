# Coverage and summaries

`@lervo/context-coverage` rebuilds one report from canonical events, retaining every E1 reason, E2 version and revision, enhanced E3 coordinate, valid E4, highest evidence, and missing stage. Delivery, reference, relevance, and selection ratios remain separate. Unknown denominators are `null` with a reason; no combined score exists.

A managed-run search summary may project only the count and sorted unique document IDs from canonical E4 evidence as `referencedDocuments` and `referencedDocumentIds`. It excludes bodies, paths, prompts, provider output, credentials, and expected evaluation identifiers. Evidence events remain canonical.

Unmanaged observations use `prepared -> referenced`, never E1–E4. Preparation proves only hook-side construction. Under the [terminal observation contract](../../events-and-privacy/terminal-observations/context-reference-and-turn-evidence.md), a reference can be a matching hash-bound `lervo-ref:` citation against a loaded document (`output_citation`) or an exact selected-path mention in the last assistant message (`path_mention`). Path mentions require a proven closing turn and selections bound to its context, provider, session and turn. The selected set combines delivered compact pointers with agent-query selections; pointer bodies need not be loaded, so path references can occur with zero loaded documents.

A selected path must stand alone between message boundaries, whitespace, quotes, backticks, brackets, parentheses or punctuation; a numeric `:line` suffix is accepted. A substring within a longer path creates no reference. A path mention proves only that the reply named the document, not reading or reliance. Neither reference form establishes managed delivery or internal use. Lervo neither rewrites nor stores that output.
