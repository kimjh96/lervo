# Conversation knowledge-job lease and source preflight

The local event chain is the job authority. A capacity-bounded destination outbox is its rebuildable queue. A background worker claims one `knowledge:conversation` row, then re-reads that exact event-and-destination row and the canonical event before source inspection and again after any asynchronous source read. The row must still be leased to the same worker at the same claim time, expiry, and attempt count, and observation must fall inside the lease. A missing, expired, acknowledged, rescheduled, or reclaimed row produces `knowledge_job_lease_conflict` and grants no further work authority. This preflight does not renew the lease or publish an outcome. Effects must revalidate the lease again at their own boundary.

Only a version-3 `pending_background` repository-work completion or historical version-2 `baseline_valid` completion is eligible. Any other event produces `knowledge_job_completion_invalid`. The changed-source path loads the exact content-addressed manifest and inspects current Git/worktree coordinates; it returns `ready_for_review`, `stale`, or `needs_review` with bounded source reason codes. The historical path returns `needs_review` with `legacy_source_unavailable`; it never invents an old manifest or claims currency. A missing or invalid manifest retains the typed `knowledge_job_source_unavailable` or `knowledge_job_source_invalid` failure. None of these preflight states proves semantic review, canonical edits, knowledge lint success, or delivery.

Queue state stores only event and destination IDs, worker lease coordinates, attempt count, bounded failure code, and timestamps. The preflight returns source paths only inside the owner process for the later scoped agent review; it writes no event or user-owned file. Public events and status exclude source bytes, prompts, provider output, absolute paths, credentials, and raw exceptions. Queue acknowledgements require a separate canonical terminal outcome and exact live lease; a successful preflight is never acknowledged as completed work.

The resolution event's `agentId` identifies the separately assigned background knowledge agent, not necessarily the live conversation worker in the completion. Reconciliation matches the completion event/hash, source event, deterministic job ID, and source-manifest coordinate; it must not equate those two agent identities. The outcome writer must prove its own active agent and exact assignment lease before append and acknowledgement. A matching completion coordinate alone does not authorize a worker outcome.

The read-only semantic reviewer additionally checks the exact knowledge-job assignment provenance, named active agent, role and capability binding, source-path set, verification suites, and unexpired assignment lease before provider work and after its response. It runs through the provider-neutral no-capability JSON runner in a separate private temporary directory, with no model tools or retained session. Exact before/after source bytes and content-hash-matched canonical context are passed through process stdin only, up to 256 KiB; binary source and oversized input fail without truncation. Changed source yields `stale/source_bytes_changed`; changed instruction bytes yield `needs_review/review_context_stale`, while missing or over-bound required context yields `needs_review/review_context_unavailable` or `needs_review/review_context_limit_exceeded`. Invalid context, provider boundary or response, and absent usage retain typed non-success failures. A valid model result is only a private semantic candidate (`implementation_only`, `canonical_change_candidate`, or `needs_review`), never an event, write grant, queue acknowledgement, or `current` claim. Any later write requires its own narrow assignment, integration, and canonical knowledge outcome.

The dormant non-success outcome writer accepts a version-3 content-bound completion or historical version-2 `baseline_valid` completion, its exact live outbox lease, and an active source-scoped read-only knowledge assignment for the separate background agent. For version 3 it reloads the CAS manifest and current source coordinates before writing. `stale/source_bytes_changed` requires observed source drift; a source-currency failure cannot be asserted against a ready source. For historical version 2, only `attention_required/legacy_source_unavailable` or a legitimately exhausted retry is allowed: the outcome carries `legacy_unavailable`, never an invented source hash or a stale/current claim. Within one event-store transaction it rechecks the queue lease, appends at most one deterministic `conversation.repository_knowledge.resolved` event, and acknowledges that same lease. A schema/append failure rolls back the acknowledgement. The event carries only bounded IDs, hashes, state, attempt count, and failure code; neither source bytes nor raw provider failure appear. `knowledge_resolution_invalid` means the proposed non-success state or bounded failure code contradicts the observed source/attempt state; `knowledge_resolution_conflict` means the canonical completion, attempt, or existing resolution changed. Neither code is a success claim. This writer cannot produce `current`; that outcome still requires reviewed canonicalization, ordered migration/refresh/lint, and a separate verified producer.

The logical retry budget is 16 work attempts. A crash or lease expiry at the ceiling may require another queue claim solely to recover and record `attention_required/knowledge_retry_exhausted`; that recovery claim does not authorize another semantic work attempt. The event's bounded `attemptCount` remains 16 while the operational outbox lease count may be greater. `knowledge_retry_exhausted` is invalid before the ceiling. A source that has become stale instead records `stale/source_bytes_changed` from observed evidence. This prevents an expired sixteenth lease from leaving a permanently pending job without falsifying knowledge currency.
