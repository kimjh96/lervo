# Conversation knowledge-job lease and source preflight

The local event chain is the job authority. A capacity-bounded destination outbox is its rebuildable queue. A background worker claims one `knowledge:conversation` row, then re-reads that exact event-and-destination row and the canonical event before source inspection and again after any asynchronous source read. The row must still be leased to the same worker at the same claim time, expiry, and attempt count, and observation must fall inside the lease. A missing, expired, acknowledged, rescheduled, or reclaimed row produces `knowledge_job_lease_conflict` and grants no further work authority. This preflight does not renew the lease or publish an outcome. Effects must revalidate the lease again at their own boundary.

Only a version-3 `pending_background` repository-work completion or historical version-2 `baseline_valid` completion is eligible. Any other event produces `knowledge_job_completion_invalid`. The changed-source path loads the exact content-addressed manifest and inspects current Git/worktree coordinates; it returns `ready_for_review`, `stale`, or `needs_review` with bounded source reason codes. The historical path returns `needs_review` with `legacy_source_unavailable`; it never invents an old manifest or claims currency. A missing or invalid manifest retains the typed `knowledge_job_source_unavailable` or `knowledge_job_source_invalid` failure. None of these preflight states proves semantic review, canonical edits, knowledge lint success, or delivery.

Queue state stores only event and destination IDs, worker lease coordinates, attempt count, bounded failure code, and timestamps. The preflight returns source paths only inside the owner process for the later scoped agent review; it writes no event or user-owned file. Public events and status exclude source bytes, prompts, provider output, absolute paths, credentials, and raw exceptions. Queue acknowledgements require a separate canonical terminal outcome and exact live lease; a successful preflight is never acknowledged as completed work.

The read-only semantic reviewer additionally checks the exact knowledge-job assignment provenance, named active agent, role and capability binding, source-path set, verification suites, and unexpired assignment lease before provider work and after its response. It runs through the provider-neutral no-capability JSON runner in a separate private temporary directory, with no model tools or retained session. Exact before/after source bytes and content-hash-matched canonical context are passed through process stdin only, up to 256 KiB; binary source and oversized input fail without truncation. Changed source yields `stale/source_bytes_changed`; changed or unavailable instruction context yields `needs_review/review_context_stale`. Invalid context, provider boundary or response, and absent usage retain typed non-success failures. A valid model result is only a private semantic candidate (`implementation_only`, `canonical_change_candidate`, or `needs_review`), never an event, write grant, queue acknowledgement, or `current` claim. Any later write requires its own narrow assignment, integration, and canonical knowledge outcome.
