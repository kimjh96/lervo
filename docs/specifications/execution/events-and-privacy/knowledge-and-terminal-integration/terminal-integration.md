# Terminal integration and activation receipts

`terminal.integration.applied` records the contract, providers, provider-target path digests and after-hashes, generated-runtime path digest and after-hash, the hash binding the provider hook operations (field `approvalHash`, kept for event compatibility; ADR-0561 removed the approval itself), and time. The actor is always the system. It excludes prompts, bodies, raw configuration, commands, runtime bytes, credentials, absolute paths, and output. Failure rolls back and emits no success event.

Bounded provider and event activation receipts contain provider, event, result, time, and bounded hashes and counts. They prove only that the Lervo hook endpoint executed or prepared context—not that the provider launched, accepted, understood, referenced, or used it. Status labels this evidence `hook_endpoint_observed_not_provider_authorship`.

Receipt failure blocks the hook. Status validates receipts against events, distinguishes endpoint observation from readiness, and emits a provider-specific action until every required event is observed. Lervo never changes local or global hook trust.

Under ADR-0539, `runtimeAfterHash` binds the tracked launcher. The runtime-store manifest, pointer, unavailable marker, and repair marker stay private to the host. They add no event and contain no repository paths or provider input. The pointer records the real publishing CLI entry as `publisher`; this host-local installation path is never exported. The schema-1 markers contain only `schemaVersion` and closed `code` values `hook_runtime_unavailable` or `hook_runtime_repair`.

On POSIX, store directories and the pointer require the current uid and no group or other writes. Parent symlinks must stay inside the user's real home. Windows ACL checks remain deferred. Missing files after pointer read, including import, retry the pointer once and then exit 0 as unmanaged. Malformed manifests, byte-count or hash mismatch, symlinks, and ownership violations exit 2 and request repair without reading hook input. Both providers interpret exit 2 as blocking UserPromptSubmit and forcing Stop continuation. Same-user verification-to-import TOCTOU is outside the contract.

Interactive installed startup publishes a differing runtime. Source-checkout startup, identified by adjacent `../src/bin.ts`, never publishes. Residents repair missing, invalid, or marked state, or a removed publisher; they recheck authority under the host lock and preserve a valid runtime from another publisher. ADR-0470 preflight verifies that runtime without tying readiness to the resident's own build. Markers trigger artifact verification on the default startup and resident paths. Repair publishes a fresh directory before switching the pointer.
