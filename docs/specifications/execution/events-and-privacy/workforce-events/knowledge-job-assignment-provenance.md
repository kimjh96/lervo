# Conversation knowledge-job assignment provenance

A background conversation-knowledge assignment is ordinary workforce state with an exclusive `knowledgeJob` provenance. Its version-1 record requires a deterministic job ID, exact completion-event ID and hash, source conversation-event ID, nullable content-bound source-manifest hash, and the durable agent ID. The nullable manifest hash means only that a historical `baseline_valid` completion lacks a version-3 source manifest; it never establishes content currency. A workstream ID, current role version and contract hash, scoped expected paths, acceptance criteria, and verification suite remain mandatory. Routine and topology provenance cannot be combined with this provenance.

The assignment ID is deterministic for project and completion event. Exact replay returns the same record; any changed provenance, role, access mode, path scope, or acceptance contract under that ID is a conflict. New knowledge-job assignments have `accessMode: read_only`; their expected paths bound source access but do not exclude an overlapping write-path claim. A claim still requires the named active agent, current role and capability binding, scoped paths, and an unexpired assignment lease. A different agent cannot take the job merely by sharing its role or provider. A read-only lease fails a write-authority check with `assignment_lease_conflict`; it does not permit an ordinary writer workspace. A separate narrow write assignment is required after review identifies an authorized canonical target. Historical assignments without `accessMode` retain `write` semantics and are not silently upgraded.

Read-only review authority rechecks the exact job provenance, source-path set, verification suites, role, capability, agent, and live lease before provider work. Any drift fails without a review or write success claim.

New `assignment.created` and `assignment.claimed` events retain `accessMode` (`read_only` or `write`) alongside their existing bounded IDs, hashes, lease coordinates, and timestamps. A malformed value fails event validation and rolls back the transition. The `assignment.created` event retains `knowledgeJobContractVersion`, `knowledgeJobId`, `knowledgeCompletionEventId`, `knowledgeCompletionEventHash`, `knowledgeSourceConversationEventId`, `knowledgeSourceManifestHash`, and `knowledgeAgentId` together. Missing or malformed coordinates fail event validation and roll back creation. Neither event includes message text, source paths or bytes, provider output, absolute paths, credentials, or raw errors. Creation and claim prove only assignment provenance and lease ownership, not agent execution, semantic review, integration, or knowledge currency. Those require their distinct workspace and knowledge-outcome evidence. A stale source, failed claim, or changed replay is not success.
