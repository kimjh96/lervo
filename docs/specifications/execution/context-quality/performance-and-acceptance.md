# Context quality performance and acceptance

Status: `proposed`
As of: 2026-10-09

This protocol evaluates [the common context-quality design](../context-quality.md). Quality, semantic parity, source integrity, latency, memory, and cost are independent gates. No combined score can compensate for a missing mandatory rule or a false delivery claim.

## Comparison coordinates

Freeze task inputs, corpus bytes, authority scope, rule and exception versions, engine and projector builds, profile, source revision, runtime, and machine/resource conditions. Record channel, execution mode, provider, and model independently. Timing comparisons alternate control and candidate; retain failed and cancelled observations and report their causes.

Deterministic comparison holds projected queries constant. Compare obligation sets, admitted source versions, ranking, packed clause/section hashes, omissions, and state/reason semantics. Origin IDs, transport formatting, receipt type, and elapsed time may differ. Provider-generated queries and answers require separate repeated end-to-end observations; exact string equality is not their acceptance criterion.

## Common conformance matrix

| Consumer                                 | Shared acceptance                                                                                   | Evidence limitation                                                                     |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Direct Codex terminal                    | Current policy, task-aware retrieval, exact section reads, budgets, cancellation and error meanings | Hook preparation does not establish controlled injection or arbitrary write enforcement |
| Direct Claude Code terminal              | Same cases and semantic assertions as Codex                                                         | Same unmanaged evidence boundary, regardless of native hook format                      |
| Managed Codex and Claude runs            | Same preparation plus exact E1-E3 and artifact checks                                               | References remain separate from internal use                                            |
| Discord conversation and repository work | Same core contract through production application composition                                       | Transport receipts do not prove provider context delivery; execution mode is explicit   |
| Native-chat fixture                      | All new shared behavior before Discord acceptance                                                   | Fixture success does not establish a shipped first-party product                        |
| Future first-party host                  | Negotiated product-host contract, same common cases, installed host journey                         | Richer presentation cannot claim stronger execution capabilities than observed          |

Normalize equivalent native requests and compare the resulting semantic input before comparing retrieval. Missing history, target paths, or scope during adapter normalization is an adapter failure, not a ranker failure. A transport with a smaller presentation limit may offer drill-down; it must not quietly lower the provider's evidence budget.

## Case population and labels

Preserve every existing reviewed regression case. Add an initial planning target of at least 100 real task families across documentation, implementation, debugging, review, release, repository operations, and short continuations. Include Korean, English, and mixed-language inputs with paired meaning where possible. This target is a starting coverage requirement, not statistical proof or authority to copy private conversations into a public benchmark.

Each case records task and corpus versions, applicable mandatory clauses, required evidence roles, acceptable alternative sources/sections, irrelevant neighbors, historical or contradictory sources, and expected observable artifact behavior. Distinguish authored, reviewed, and held-out cases. Hold out at least 30 percent of task families from tuning; translations or variants of one family cannot cross the split. Human review confirms labels before production-quality claims. Do not infer relevance from citations, agent agreement, or test-generated expected paths.

Required adverse families include zero relevant sources; ambiguous task/reference; an identifier that must not be translated; a long document with its operative clause at the end; rule conditions and exceptions in different sections; duplicate sources; authoritative supersession; conflicting rules; a new unregistered document; oversized/unreadable/invalid source; source edits between selection and loading; policy or permission change; corrupt cache; host restart; provider cancellation; overloaded preparation; and a future surface lacking a delivery capability.

Language cases include Korean conversation with English publication, an explicit bounded language exception, quotations and code that retain original bytes, a chat-only reply, and a late change of target path. Zero-hit cases must separate true no evidence from unsearched or unavailable coverage. Test provider-input boundaries against retrieved prose that attempts to redefine policy or execution authority.

## Measurements and gates

| Dimension                   | Acceptance                                                                                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Known mandatory obligations | 100 percent of applicable reviewed clauses resolved and completely loaded on successful supported plans; unresolved/conflicting cases cannot pass the affected controlled gate |
| Exact evidence              | Zero accepted stale source/section hashes, cross-scope reuse, false managed injection, or silently truncated required clauses                                                  |
| Semantic surface parity     | Identical deterministic outputs for identical semantic inputs; all differences attributable to declared capabilities or provider/transport observations                        |
| Required evidence recall    | Report at candidate and delivered-section stages, by task family/language; no reviewed deterministic case regression                                                           |
| Relevant delivered context  | Measure useful sections and irrelevant bytes, deduplicated by source version; never use reference ratio as precision ground truth                                              |
| Abstention and absence      | Report false absence, irrelevant-answer, unavailable-search, and appropriate no-evidence rates separately                                                                      |
| Artifact compliance         | Every critical policy regression case passes; report statistical task-completion and verification-unavailable rates separately for each provider and execution mode            |
| Operational cost            | Compare core and end-to-end latency, CPU, peak RSS, heap/external memory, cache bytes, context bytes/tokens, provider calls, observed usage and correction attempts            |

Before implementation measurement begins, register the minimum practical improvement, noninferiority margins, confidence method, sample count, stop rules, and cost ceilings in one immutable protocol. Existing reviewed thresholds remain a floor. Numeric retrieval and latency targets require a current baseline for the corresponding task and resource class; an unmeasured universal millisecond promise is not a design guarantee. Freeze them before observing candidate results and never loosen them to qualify a failed run.

For deterministic correctness, execute all cases on every relevant change. For performance, use at least 30 alternating fresh-process warm pairs after separately recorded warmups and at least five cold pairs, retaining all samples. Measure changed-source and concurrent-consumer runs separately. Start stochastic provider comparisons with five repetitions per case/arm/provider, then use the preregistered power or precision requirement to increase the population before making a parity claim. Five repetitions alone do not establish a small failure rate. Report intervals and denominators; unavailable measurements are not zeros.

## Performance architecture

Keep source-unit and field-analysis reuse from ADR-0499/0500. Every reused projection must bind current authorized source bytes and producer/runtime/profile coordinates. Stable exact preparation may serve many queries, but task-derived policy and authorization are revalidated per request. Caches never replace current evidence at a consequential boundary.

Measure source observation, applicability, projection, candidate retrieval, section loading, packing, delivery, verification, transport, and provider generation separately. Include process bootstrap and queue time in end-to-end timing. Compare the common core on the same resource class across surfaces; compare warm and cold lifecycles separately. Discord network or provider generation time cannot justify weaker relevance, and cold terminal startup cannot be hidden inside a warm service benchmark.

Prompt-time compact work stays local and bounded within its existing envelope and lifecycle budget. Do not add a mandatory hidden model turn, whole-corpus scan, or waiting for a background build on every prompt. Use background preparation only with exact freshness and explicit unavailability. A requested on-demand preparation can run outside the hook under its own observed budget. Existing user-facing query behavior remains available during migration.

Share expensive preparation only for compatible project, authorized scope, source generation, plan, build, and profile identities. Enforce bounded parallel work, cancellation, memory pressure, and current-generation eviction. A source change invalidates selection/packing while exact unchanged computational units may be reused. Do not retain duplicate source strings, decoded cache records, and copied ranker structures merely to report evidence.

Benchmark the smallest supported profile as well as larger profiles. A host unable to carry mandatory clauses reports insufficient capacity; it does not claim equivalent success with fewer rules. Any optional semantic service measures network, indexing, refresh, outage, export, and cost independently and preserves the explicit local rollback path.

## Candidate qualification and installed acceptance

Evaluate the current lexical plan, task/language projection, semantic retrieval, fusion, reranking, and section assembly as attributable changes. An ablation removes one candidate stage at a time while retaining mandatory obligations. A reviewed oracle-evidence control can distinguish retrieval failure from provider failure, but its results are not production performance. Keep the independent lexical baseline available; failed required stages never silently substitute it.

After source and adapter gates, qualify exact packaged builds through real Codex terminal, Claude Code terminal, and Discord journeys. Retain release/build, source, profile, model, language, state, artifact, timing, and resource coordinates without raw private text in event telemetry. Run restart, policy/source change, concurrent turn, and failure-recovery cases. Observe at least seven days of supported operation plus the preregistered task count; elapsed days without enough tasks cannot pass.

Native-chat conformance is required now for new shared behavior. Installed first-party acceptance remains pending until that product exists, and may not block truthful completion of supported existing surfaces. Never label future installed parity complete from a stub. Adoption may claim core conformance, existing-surface installed acceptance, and future-host readiness separately.

Privacy, unauthorized effect, stale mandatory-rule success, or false evidence promotion stops rollout immediately and preserves the failing observation. Quality or resource regression rejects that candidate under the frozen protocol. Roll back by exact supported plan/writer transition, without deleting canonical history or silently modifying source authority. Repair creates a new candidate and keeps the failed cohort immutable.
