# Snapshot capture

Snapshot capture creates Git tree objects through a temporary index. Index-tree observation uses an isolated copy of the user's index, including split-index staging, so Git cache updates cannot notify the coordinator of its own observation. Ordinary observation creates no export commit or ref; bundle creation and explicit history-replacement recovery create needed commits. No unchanged-head cache can authorize apply or native work without a fresh snapshot.

Replica apply preserves the host-reviewed `.lervo/knowledge/convergence-delegation.json` while cleaning source files. Cleanup excludes that exact path even when resetting to an older HEAD temporarily removes the worktree's newer ignore rule. The grant remains local authority, never enters the replica snapshot, and requires separate review on each host.

A bundle request binds the exact snapshot hash selected by reconciliation. If the source advances before bundle creation, newer bytes cannot replace the older decision's bytes. After an exact target apply, the coordinator persists the transferred snapshot as the new common base before recapturing the active source. If the source advanced concurrently, the cycle remains pending; its successor proceeds as a one-sided change rather than manufacturing dual divergence from the older base. A readiness receipt is written only after both freshly captured sides are equal.
