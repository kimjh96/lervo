# ADR-0073: 자동 수정 없는 doctor 복구 안내

- 상태: 승인
- 날짜: 2026-08-20

## 맥락

Doctor는 손상이나 확인 불가 상태를 정확히 구분하지만 issue code와 진단 문장만으로는 운영자가 무엇을 먼저 확인해야 하는지 알기 어려웠습니다. 오류 원문이나 경로에서 해결책을 동적으로 만들면 비밀정보를 다시 노출하거나 존재하지 않는 원본과 명령을 추측할 수 있습니다. 진단과 자동 복구를 결합하면 읽기 전용 doctor가 상태를 바꾸는 문제도 생깁니다.

## 결정

모든 `DoctorReport`에 `recoveryGuidance` 배열을 둡니다. 각 항목은 `issueCode`, 제한된 `actionCode`, 고정된 한국어 `message`, `actionState: not_performed`만 포함합니다. 안내는 자유 형식 오류 문장이 아니라 등록된 issue code에서만 파생합니다.

현재의 모든 issue code는 compile-time 전체 매핑을 가져야 합니다. 새 issue code를 추가하면 대응 안내도 함께 추가하지 않는 한 타입 검사가 실패합니다. 같은 issue code가 여러 event나 검사에서 반복되면 첫 등장 순서를 유지한 안내 하나만 반환합니다. 서로 다른 issue code는 action code가 같아도 별도 원인을 숨기지 않습니다. Issue가 없으면 안내도 빈 배열입니다.

텍스트 출력은 `다음 확인` 아래에 action code와 사람이 읽는 문장을 표시하고, 자동 수정이나 상태 변경을 실행하지 않았음을 한 번 더 밝힙니다. JSON은 같은 구조를 반환하므로 자동화가 안내와 실제 조치를 혼동하지 않습니다.

## 정보와 실행 경계

안내 생성기는 issue의 message와 event ID를 읽거나 복사하지 않습니다. Project ID, 원본 ID, digest, 절대·상대 경로, 문서·스킬 본문, provider 출력, credential과 내부 오류 원문을 추측하거나 포함하지 않습니다. 안내는 파일, event, Hub 원본을 만들거나 명령을 실행하지 않으며 승인·선택·검토·조치 상태를 바꾸지 않습니다.

## 결과

운영자는 오류 코드만 보는 대신 안전한 다음 확인 방향을 얻습니다. 안내는 진단 결과에서 파생된 설명일 뿐 복구 성공, 원인 확정, 실행 승인이나 자동 수정이 아니며 실제 변경은 별도 명시적 작업으로 남습니다.
