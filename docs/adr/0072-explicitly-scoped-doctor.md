# ADR-0072: 실행 범위가 명시된 doctor 조회

- 상태: 승인
- 날짜: 2026-08-20

## 맥락

전체 `lervo doctor`는 event·지식, 문서, 스킬, provider와 검색 원본을 모두 확인합니다. 검색 운영 원본만 점검하려는 경우에도 모든 검사기를 실행한 뒤 결과를 필터링하면 느리고 불필요한 외부 실행 파일 probe가 생기며, 제외된 문제를 정상으로 오해할 수 있습니다. 반대로 검색 항목만 정상인 결과를 프로젝트 전체 정상으로 표시해서도 안 됩니다.

## 결정

`lervo doctor`의 기본 범위는 `all`이고 `--scope search`를 명시하면 검색 엔진 선택, rollout 정책, 검토와 조치 네 검사만 실행합니다. 지원하지 않는 범위는 project 원본을 열기 전에 거부합니다. 범위 제한은 전체 검사 뒤의 출력 필터가 아니라 실행 계획입니다.

모든 `DoctorReport`는 `scope`를 필수로 반환합니다. 검색 범위의 텍스트 출력은 검색 항목만 확인했고 프로젝트 전체 상태가 아님을 함께 표시합니다. JSON도 `scope: "search"`와 실제 실행한 네 검사만 포함합니다. 종료 코드 0은 요청한 범위의 모든 항목이 `healthy`라는 뜻이며 다른 범위의 상태를 주장하지 않습니다.

검색 범위는 project manifest만 읽고 event store와 CAS를 열지 않습니다. 문서·스킬 검사와 Codex·Claude runtime probe도 호출하지 않습니다. 검색 운영 resolver가 등록 corpus를 검증하기 위해 읽는 문서 manifest와 원본은 검색 자체의 필수 입력이므로 이 범위 안에 남습니다.

## 무부작용과 확장 경계

범위 조회는 파일·event·Hub 원본을 만들지 않고 상태를 전진시키지 않습니다. 새 범위를 추가할 때는 허용되는 검사 ID 집합과 실제 실행 계획, 출력의 범위 설명을 함께 추가해야 하며 제외한 검사를 빈 정상 결과로 채우지 않습니다.

## 결과

운영자는 필요한 검색 진단만 빠르게 실행할 수 있고 자동화는 JSON의 `scope`로 결과 의미를 확인할 수 있습니다. 제한 조회의 성공을 전체 프로젝트의 건강 상태로 오해하지 않으면서, 이후 다른 명시적 범위를 같은 계약으로 확장할 수 있습니다.
