# ADR-0503: Compile schema validators at build time

Status: `accepted`
Decision date: 2026-10-11

## Context

The [bundled query diagnosis](../../../evidence/quality/context-quality/overview.md#bundled-query-diagnosis) identifies eager compilation of 209 schemas as a substantial fresh-process startup cost. Validation itself remains required at every existing boundary. Generated code must preserve invalid-input errors as well as accepted values, and must fit the existing terminal runtime size limit.

## Decision

The schemas package owns a build-only compiler and a declarative catalog. Its public `validateSchema` facade calls generated validators without constructing Ajv or evaluating generated strings at runtime. Existing schema names, schema definitions, date-time semantics, verdicts and error arrays remain the contract. The private package import resolves authored types before a build and generated JavaScript during execution; existing validation exports are unchanged. The private package also exposes the owned JSON parser described below.

Generation retains strict mode, all errors and inline references. Required-property and enum loops use thresholds 1 and 3, and code optimization uses level 2. These settings affect generated representation, not validation policy. Disabling inline references is rejected because fixture comparisons exposed different `schemaPath` errors. The original runtime compiler settings remain the test oracle.

Generator version 4 retains the primitive enum indexing introduced in version 2. It indexes static primitive enum lists that meet the existing enum-loop threshold. Its build-only keyword adapter retains Ajv's error definition and uses the original compiler for short lists, object/array members and request-defined `$data` enums. The generated runtime lazily creates one membership set per referenced schema array. A private weak map owns those sets; its keys and members come only from the finite compiled catalog, never requests, repository observations or caller-provided enum lists. The generated artifact size limit also bounds the source catalog represented by those indexes. No accepted-value cache is introduced.

The public validation facade deep-copies failed error arrays, including nested parameters. Returning the generated validator's enum array allowed a caller to add an unsupported event type and change subsequent validation. Error contents and ordering remain unchanged, but their mutable objects no longer alias shared schema definitions. The private generated validator and its static enum arrays are not public package exports.

`packages/schemas/scripts/generate-validators.mjs` owns exactly four replaceable files in `dist/generated`: `validators.js`, `selected-validators.js`, `coordinate-data-validators.js` and `manifest.json`. The manifest requires schema and generator versions, sorted repository-relative source paths and SHA-256 hashes, their aggregate hash, schema count, Ajv/esbuild versions, compiler options, output hash and byte length. The `selected` object requires the exact sorted twelve schema names, their generated output hash and byte length. The full and selected outputs come from the same complete catalog compilation in canonical order; selected function bodies remain identical to their full-map counterparts. Source identity includes all schema TypeScript, the lockfile, package configuration and generation/verification owners, including the selection contract and coordinate-branch compiler. It detects drift; it is not an independent build attestation. No absolute workspace paths, timestamps or request content enter these artifacts.

The compiler also derives a sorted, bounded `runtimeDependencies` inventory from the generated bundle's actual inputs. Release snapshot and SBOM owners combine this inventory with the outer bundle inputs. Ajv runtime helpers and `fast-deep-equal` therefore retain their package identities even though the outer bundle sees one generated file; compiler-only URI and schema-traversal dependencies leave the bundled inventory. The release checker keeps an exact reviewed package set.

Generation exclusively creates one fixed `.generation` staging directory, writes the four files and then renames each output. An interrupted set cannot pass the content/source check. Only the invocation that acquired the directory removes it during cleanup. An occupied stage stops another generator before compilation; after confirming no generator is active, the build owner can remove the retained stage and regenerate this disposable set. Repeated attempts cannot accumulate per-run directories. Manifest input is capped at 256 KiB, each generated JavaScript file at 16 MiB, and source inventory at 1,024 paths. Linked output files or a linked generated directory are rejected.

The package build generates before TypeScript compilation. Vitest verifies or regenerates once before source imports. CLI, Hub and Node bundle owners require a current exact generated set before bundling; missing or stale artifacts cannot silently trigger runtime compilation. Ordinary package, Hub and terminal-hook consumers retain the complete embedded map.

The internal shared CLI/Node module uses a distribution-owned loading adapter. Its main ESM output embeds the twelve selected validators; `repository-runtime-validators.cjs` contains the complete canonical map and loads synchronously on the first unselected lookup. Invalid selected inputs never retry through fallback. The public validation facade and its error-copying behavior remain unchanged. The complete runtime inventory binds both files, and installation must include both even when a selected-only journey does not load fallback. There is no public SDK, runtime compiler, request-value cache, code-cache generation or V8 flag change. First fallback loading remains part of the calling operation and whole-process accounting.

### Owned coordinate JSON parsing

`parseEventWriterCoordinateJson` owns `JSON.parse` and returns a schema-valid coordinate or `null`; invalid JSON still throws its original syntax error. Ordinary package, Hub and terminal consumers use the complete validator map. Only the internal shared CLI/Node build replaces this parser's private validation import with generated coordinate branches. The distribution plugin matches the parser importer exactly. Adding every branch to the terminal bundle exceeded its 8 MiB budget, so that additional representation is confined to the shared runtime; the budget remains unchanged.

The branch compiler uses the canonical coordinate schema and unchanged strict/all-errors/inlining options. It accepts only a root containing schema metadata and `oneOf`, with six object branches requiring distinct integer `selectedEventSchemaVersion` constants 1–6. Missing, overlapping or otherwise unsupported discriminators and additional root constraints stop generation. This proof allows the shared runtime to validate the applicable complete branch without constructing errors for other versions. The manifest's `coordinateData` descriptor binds the exact version list, output digest and size. No accepted-input cache or request priming is added.

The public arbitrary-object `validateSchema` and `readEventWriterCoordinate` paths retain full validation and their error contracts. Only the private file reader uses owned parsing after its existing bounded, no-follow, stable file read. It retains syntax/schema failure distinctions, expected-project checks, reader capability evidence, activation identity and cloning. The post-schema continuation remains internal to the project package. Schema-valid bytes do not grant authority or a publication receipt.

The release-impact classifier treats the compiler, keyword adapter, generator and artifact-verification owners as released tooling. Changing only one of these build-time files can alter packaged behavior, so it requires reviewed release intent even when runtime source files are unchanged.

The terminal bundle is minified to preserve its unchanged 8 MiB bound. Function names are not retained as a separate runtime contract. CLI, Hub and Node bundle formatting remains unchanged. Installed hook integrity and observable error behavior require consumer verification of the final bytes.

## Failure and privacy

This change adds no event, repository state, user configuration or telemetry claim. The finite enum indexes retain only schema constants for the generated module's lifetime. The manifest contains public source coordinates and hashes only. Source limits or linked source entries fail with `schema_validator_source_limit` or `schema_validator_source_invalid`; malformed, linked or oversized artifacts fail with `schema_validator_artifact_invalid`; changed source, options or output fail with `schema_validator_artifact_stale`. Oversized generation fails with `schema_validator_artifact_limit`. Filesystem, parse and compiler errors stop the build. A missing selected name in the compiler catalog fails with `schema_validator_selection_invalid`; an unsupported coordinate discriminator or root constraint fails with `schema_coordinate_discriminator_invalid`. An unavailable or corrupt full-map module fails the requesting operation; it never accepts input permissively. Existing aggregate artifact verification rejects missing or changed distribution members before installation.

## Verification and completion

Differential tests compare every catalog name, all existing JSON fixtures and field mutations against the prior compiler, including exact error arrays. Selected-function tests compare exact generated bodies; the distribution adapter is tested with every schema, fixture mutations, property-key coercion and first fallback loading. A separate process forbids code generation from strings. Clean-copy tests typecheck before generation, build without prior output, execute the public package and compare generated bytes and manifests across different absolute roots. Artifact tests reject missing, linked, changed and mismatched inputs, including the coordinate map and version list. Owned-parser tests compare all six coordinate versions and malformed nested JSON against full validation, preserve syntax/schema failures and file guards, and reject compiler inputs that cannot prove branch exclusivity. Shared-runtime tests verify that parser-only bundles contain the coordinate map without importing the complete map. These tests do not qualify end-to-end performance.

Full regression, package boundaries, generated release metadata, supported installed consumers and exact terminal size remain required. Fresh-process diagnostics must bind the new executable bytes and preserve the earlier observations. Lower startup cost does not satisfy the independently frozen timed-core resource gates, reviewed real-task quality, production rollout or operational observation requirements.
