# ADR-0481: Bind generated projections by hash in lifecycle plan review

Status: `accepted`
Decision date: 2026-10-06
Amends: [ADR-0479](0479-park-rejected-semantic-candidates-and-settle-opaque-assets-by-the-delegation-suite.md)
Amended by: [ADR-0483](0483-reevaluate-settled-semantic-candidates-once-per-evaluation-contract.md) (contract identifies the evaluation module)

## Context

After ADR-0479 was deployed as `main` `bafdf86d`, the WSL `axli` resident ran the new runtime and recorded `attention_required/knowledge_source_limit_exceeded` at `assessment` again, at 14:09:56 UTC on 2026-10-06. The private stack again named `reviewLifecyclePlan`, this time at the second bound, the one that covers the plan, sources, and context together.

ADR-0479 had already limited the disclosed sources to the paths the plan changes. Of the 30 changed paths in `axli`'s layout plan, every one is marked `ownership: lervo_generated`. One of them, `.lervo/state/knowledge/current/inventory.json`, is a stale 4,859,481-byte rebuildable inventory. Its current bytes were disclosed as a reviewed source, which exceeded the 1 MiB bound by itself. The same plan, with that projection bound by hash, needs about 250 KB.

The failure settled under `evaluationContract: "adr-0479"`, so the runtime correctly does not loop on it. It stays settled until the source changes.

## Decision

- Operations that the plan marks `lervo_generated`, without a `destinationPath`, are rebuildable projections written by deterministic Lervo code. Examples are the knowledge inventory, source units, structural concepts and manifests, the document layout, and `docs/knowledge` pages. The reviewer receives their path, their current `contentHash`, and `ownership: lervo_generated`, but not their current bytes. Their operations in the disclosed plan keep `desiredHash` and `expectedCurrentHash`, drop `content`, and add `contentDisclosed: false`.
- The plan hash still binds every byte of the complete plan. Apply still checks the exact plan, preimages, lint, and the pinned suites. User-owned and managed-block operations, and every move, keep their full bytes.
- Review context is loaded only for the paths that remain reviewable. The 1 MiB bound applies to the disclosed request. The prompt states that withheld generated bytes are not missing source bytes.
- The stage-failure evaluation contract becomes `adr-0481`. A source-limit failure settled under `adr-0479` is reevaluated once, so `axli` resumes after the upgrade without an owner command.

## State, events, privacy, and failure meaning

No event type, state, or failure code is added. `knowledge_source_limit_exceeded` from lifecycle plan review now means the disclosed user-owned scope of one plan exceeds 1 MiB. Generated bytes were already private local state. They are now sent to the provider less often.

## Verification

A focused regression must show a 4.8 MB stale generated inventory bound by hash, a user-owned operation still disclosed in full, and a review request within its bound. The same test must fail with `knowledge_source_limit_exceeded` on the ADR-0479 runtime. A pure test must show that a limit settled under `adr-0479` is reevaluated once, while one settled under `adr-0481` stays settled.

Installed verification must show `axli` leaving `knowledge_source_limit_exceeded` after the upgrade.
