# ADR-0481: Bind generated projections by hash in lifecycle plan review

Status: `accepted`
Decision date: 2026-10-06
Amends: [ADR-0479](0479-park-rejected-semantic-candidates-and-settle-opaque-assets-by-the-delegation-suite.md)
Amended by: [ADR-0485](0485-reevaluate-settled-semantic-candidates-once-per-evaluation-contract.md) (contract identifies the evaluation module)

Amended by: [continuation and relocation](../../../specs/repository-knowledge-entrypoints-and-continuation/continuation-and-relocation.md) (a plan that derives a generated file from an unchanged source sends that source's bytes as review `evidence`)

Amended by: [ADR-0653](0653-never-let-one-large-document-stop-repository-knowledge.md) (moved documents are reviewed by hash and rewritten lines)

## Context

After ADR-0479 deployed as `main` `bafdf86d`, the WSL `axli` resident ran the new runtime but again recorded `attention_required/knowledge_source_limit_exceeded` at `assessment`, at 14:09:56 UTC on 2026-10-06. The private stack identified `reviewLifecyclePlan` at the second bound, covering the plan, sources, and context together.

ADR-0479 limited disclosed sources to changed paths. All 30 changed paths in `axli`'s layout plan have `ownership: lervo_generated`. One, `.lervo/state/knowledge/current/inventory.json`, is a stale, rebuildable 4,859,481-byte inventory. Disclosing its current bytes as a reviewed source exceeded the 1 MiB bound by itself. Binding that projection by hash reduces the same request to about 250 KB.

The failure settled under `evaluationContract: "adr-0479"`, correctly preventing retries until the source changes.

## Decision

- Operations marked `lervo_generated` by the plan and lacking a `destinationPath` are rebuildable projections written by deterministic Lervo code. Examples include the knowledge inventory, source units, structural concepts and manifests, document layout, and `docs/knowledge` pages. The reviewer receives their path, current `contentHash`, and `ownership: lervo_generated`, but no current bytes. Their disclosed plan operations retain `desiredHash` and `expectedCurrentHash`, omit `content`, and add `contentDisclosed: false`.
- The plan hash still binds every byte of the complete plan. Apply still checks the exact plan, preimages, lint, and pinned suites. User-owned operations, managed-block operations, and every move retain full bytes.
- Review context is loaded only for paths that remain reviewable. The 1 MiB bound applies to the disclosed request. The prompt states that withheld generated bytes are not missing source bytes.
- The stage-failure evaluation contract becomes `adr-0481`. A source-limit failure settled under `adr-0479` is reevaluated once, allowing `axli` to resume after upgrade without an owner command.

## State, events, privacy, and failure meaning

No event type, state, or failure code is added. `knowledge_source_limit_exceeded` from lifecycle plan review now means one plan's disclosed user-owned scope exceeds 1 MiB. Generated bytes remain private local state and are sent to the provider less often.

## Verification

A focused regression must show a stale 4.8 MB generated inventory bound by hash, a user-owned operation disclosed in full, and a review request within its bound. The same test must fail with `knowledge_source_limit_exceeded` on the ADR-0479 runtime.

A pure test must show that a limit settled under `adr-0479` is reevaluated once, while one settled under `adr-0481` stays settled.

Installed verification must show `axli` leaving `knowledge_source_limit_exceeded` after upgrade.
