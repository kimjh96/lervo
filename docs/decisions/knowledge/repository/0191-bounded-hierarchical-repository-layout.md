# ADR-0191: Bounded hierarchical repository layout

Status: `accepted`

As of: 2026-08-23

## Context

Splitting independent topics into separate files prevents append-only documents, but a flat directory can still become an unbounded catalog. Lervo also previously published human-facing navigation at repository-root `knowledge/`, which separated related documentation from `docs/` without making it internal state.

Human documentation and machine registries have different navigation needs. People need stable semantic neighborhoods. Content-addressed registries need deterministic distribution that does not depend on subjective classification.

## Decision

- Human-readable source and generated navigation remain visible repository content under `docs/`; they do not move into hidden `.lervo` control state.
- The default generated publication root is `docs/knowledge`. Existing generated bytes move through the structural migration plan and remain protected by generation manifests.
- Decision records move from flat `docs/adr` into configured routes below `docs/decisions`. ADR numbers remain identity, and migration uses the tracked repository taxonomy before requiring exact per-document approval.
- A decision leaf may contain at most 24 ADR documents. Documentation lifecycle checks reject a flat legacy ADR directory or an overfull leaf.
- ID-addressed Lervo registries and rebuildable state use two-hex fan-out: `<registry>/<digest-prefix>/<artifact-id>.<extension>`.
- Readers accept legacy flat artifacts during migration, reject duplicates and incorrectly sharded records, and writers emit only canonical sharded paths.
- `lervo migrate knowledge` moves legacy machine artifacts without user-byte approval and moves user documents only with exact item approval.
- Apply, rollback, and deletion prune empty directories. Initialization creates only directories required by files that exist.

## Consequences

The repository keeps a short, visible documentation surface while `.lervo` remains policy, provenance, generated manifests, and local state. A clean clone can reproduce machine indexes from canonical repository content, and no single registry directory grows linearly with repository history.

ADR-0192 refines the original classifier: routes are repository-scoped and classification fails closed instead of using `foundation` as a fallback.
