# ADR-0610: Write Lervo effects only on the base branch, as commits

Status: `accepted`
Decision date: 2026-11-22
Amends: [ADR-0561](../../foundation/0561-decide-without-the-owner-cross-check-reversible-effect-notice.md) (every effect lands as its own commit), [ADR-0478](../../coordination/sync/0478-renew-each-delegation-with-one-writer.md) (the delegation stays untracked)

## Context

On 2026-11-22, three owner checkouts held Lervo's bytes as uncommitted changes: Mac axli (detached HEAD), Mac plen and WSL plen (feature branch `fix/home-data-freshness`). The bytes were:

- the terminal hook launcher;
- `.lervo/knowledge/document-layout.yaml` and the instruction bridges;
- the Lervo block of `AGENTS.md`;
- generated owner rules;
- the convergence delegation.

Some were 3 weeks old. Four paths left them there:

- An upgrade or background stage applied a generated-only (`ready`) plan without a commit. ADR-0561 committed only reviewed effects.
- The terminal integration stage wrote the launcher and hook files without a commit.
- A host without Hub coordination wrote an applied owner rule and left the commit to the owner.
- ADR-0478 meant the delegation to be untracked, but only `lervo init` writes the ignore line. Older repositories still tracked it, so every renewal left it modified.

Committed effects had a second flaw. They landed on whatever branch was checked out, so Lervo's commits could enter the owner's feature-branch pull request.

## Decision

### Only the base branch receives Lervo's effects

`checkoutOnBaseBranch` decides whether Lervo may write and commit its own effect in a checkout:

- The base is the remote default branch the clone recorded in `refs/remotes/origin/HEAD`, when the branch it names still exists.
- Without that, the base is a local `main`, then `master`.
- When none exists, the checked-out branch is the only line of work and qualifies.
- A detached HEAD never qualifies.
- A directory outside Git, or a repository whose HEAD has no commit yet, has no branch work to protect and qualifies. There a generated-only effect applies without a commit, as before; a reviewed effect still needs one.

Off the base branch, nothing is written. The work waits and lands once the checkout is back on the base branch:

- `knowledgeEffectPreflight` returns `commit_unavailable` with detail `not_on_base`, and `applyCommittedKnowledgeEffect` refuses before it applies.
- A knowledge resident cycle stops after its host-local terminal-skill observation and returns `busy` with `repository_not_on_base`. It is classified as `waiting`, so it backs off instead of spinning. Pending stages and owner turns stay due.
- `lervo upgrade` plans the knowledge stage as `lervo_debt` with reason `not_on_base` and skips it on apply. It plans the terminal integration stage as Lervo debt whenever its preflight holds: `not_on_base`, another `commit_unavailable` detail, `paths_uncommitted` or `owner_hold`. The other stages still apply.
- Stored owner-rule candidates stay stored, whether the resident or `lervo knowledge instruction intake` would apply them.

### Every effect lands as its own commit

Generated-only plans no longer skip the commit:

- A background lifecycle plan without review, whether layout, instruction bootstrap, bridge or knowledge migration, runs the same preflight and lands through `applyCommittedKnowledgeEffect`. Its notice reads `not required: only Lervo-generated bytes changed`.
- In the CLI, the `ready` layout plan, the `ready` instruction bridge and the structural knowledge migration apply through `applyGeneratedEffect`. It runs the same preflight and commit as a cross-checked effect.
- The terminal integration stage commits the launcher and hook files Git would carry after its post-apply verification, with effect `terminal_integration`. Ignored host-local hook files need no commit, so they never hold the stage, even on a host that does not own convergence. The upgrade re-inspects the stage at apply time and reports a commit that did not land.
- A single host commits an applied owner rule as a Hub owner does.

Lervo's own commits skip the owner's commit hooks (`--no-verify`). A hook that formats or rejects them would otherwise leave an applied effect uncommitted, or roll it back and hold it forever.

Two effect kinds are added: `knowledge_migration` (`docs: refresh the generated repository knowledge`) and `terminal_integration` (`chore: refresh the Lervo terminal hook launcher`).

### The delegation becomes host-local in older repositories

On the base branch, the resident's `keepConvergenceDelegationHostLocal` makes one `Lervo Knowledge` commit. The commit adds `knowledge/convergence-delegation.json` to `.lervo/.gitignore` and removes the delegation from the index. A private index builds it, so the owner's other staged entries are neither captured nor changed. The file stays on disk. The ref moves only from the HEAD the commit was built on.

Pulling that commit makes Git delete the file in another checkout. The delegation loader therefore keeps a copy of the last delegation it read under `.lervo/state/knowledge/`. The loader restores that copy only when the delegation is missing, ignored and absent from HEAD, and the last commit touching its path is the untracking commit. It restores once per such commit, so a later removal by the owner stands. A delegation Lervo did not untrack is never restored. A failed untracking attempt puts `.lervo/.gitignore` back as it was, removing it if Lervo created it.

## Consequences

- An owner who stays on a feature branch defers Lervo's repository maintenance there until they return to the base branch. The checkout switch wakes the resident. A convergence owner host on a feature branch also defers convergence for its peers, which wait on that owner.
- The existing uncommitted copies in Mac axli, Mac plen and WSL plen stay until the owner discards or keeps them. The next run on the base branch applies the same plans again as commits.
- An explicit owner command such as `lervo knowledge revert` still commits where the owner runs it.
- No event, attention item or wire format changes. `commit_unavailable` already carried a free-form detail, and the new effect kinds are new trailer values.
