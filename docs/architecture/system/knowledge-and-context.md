# Repository knowledge and context

## Repository knowledge

A bounded scanner, typed source adapters, and deterministic structural compiler project repository evidence without assuming folder names. Isolated capability-free providers may propose source-cited semantic or normalization candidates. Reviewed Markdown and semantic records remain canonical.

```text
repository sources
  -> typed inventory + stable source units
  -> structural plan -----------------> bounded publication + sidecars
  -> isolated semantic compiler
  -> reconcile -> human review ------> claims, relations, semantic pages
  -> lint / impact / query / context delivery
```

[Repository knowledge and document ownership](../repository-knowledge.md) details source, projection, normalization, routing, and failure boundaries.

## Document ownership

Every document has one write model: user-owned bytes, exact managed blocks, or proven Lervo-generated output. Provider entrypoints retain user regions. AGENTS carries only a fixed-size registry bootstrap; CLAUDE imports it through a managed bridge. See [document ownership](../repository-knowledge.md#document-ownership).

## Search and context

Search recommends but does not prove use. The product-qualified Lexical v2 engine and projected retrieval plan are the no-transition product defaults. Lexical v1 remains the independent local and release-rollback baseline.

Repository-specific engines use the compatibility engine-selection chain. Different composed local or external retrieval uses a separate content-bound complete-plan selection above the same provider-neutral ports. Explicit local selections retain reviewed activation, current runtime validation, and fail-closed stage behavior. Ordinary managed runs do not add linked-only context after search.

[Search and context boundaries](../search-and-context.md) details engine ownership, extension steps, evidence states, and failure behavior.
