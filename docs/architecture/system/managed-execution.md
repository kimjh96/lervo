# Managed execution and terminal evidence

## Managed admission and activation

Before effects, the provider grounds requests into validated typed decisions. Orchestration resolves role, policy, skills, capabilities, context, write authorization, and verification. Adapters normalize native telemetry. Activation is confirmed once after E3 and before the write bridge or task turn; failure closes the session without an activation-success event.

Managed runs require a verified workstream delivered with E1–E3. After reader-first writer activation, each managed admission records one provider-neutral causal event before `run.requested`. Version-1 writers and invalid ancestry block provider startup.

Deliberation uses one control root and explicit child relationships. Work IDs aggregate evidence but grant no objective, assignment, or completion authority.

## Coverage and publication

`@lervo/context-coverage` projects managed coverage once from canonical events. Enhanced E3 binds injected receipts to exact document versions. Validated adapter results retain only their digest and turn coordinates; exact returned tokens may create E4 output citations.

Evidence-bearing sources and human publication have separate coordinates: only current-envelope evidence metadata is removed before publication evaluation and storage. Local and Hub projections use the same projector and never equate delivery or citation with understanding or internal use.

## Direct provider terminals

Direct provider terminals use a narrower native-hook path. Every prompt performs a fail-closed query and receives exact-hash context. Stop checks knowledge currency and may observe exact context-reference markers. New markers are standalone Markdown HTML comments; legacy plain v1 tokens remain accepted.

Privacy-bounded preparation, reference, and turn events prove neither provider acceptance nor internal use. They cannot satisfy managed E1–E4 because Lervo did not create or fully observe the provider process.

Terminal integration merges approved handlers into Codex and Claude hook configuration without replacing provider settings. Invalid or conflicting configuration blocks migration. Opaque coordinates bind prompt and Stop events without raw provider IDs or conversation text. An exact managed worktree binds one writer and generation without claiming managed-provider telemetry.

Direct hooks prepare at most 8 KiB and retain bounded coordinates. Unattached and integrator Stop require global checkpoints for changed revisions. Worker Stop validates its workspace, writer, lease, and scoped diff and records a private checkpoint; foreign global movement is informational.

## Headless application boundary

The headless application boundary rebuilds assignment, attempt, resource, next-action, [operating-attention](../../specifications/execution/operating-attention.md), and [operating-liveness](../../specifications/execution/operating-liveness.md) reports. Root heartbeat and managed-process point-in-time evidence remain separate.

`@lervo/application-contract` owns public shapes. Pure projectors compose existing authorities without bypassing lease, approval, verification, event, or recovery rules.

The bounded unattended scheduler is an application composition over that same report. Pure selection, workforce claim, foreground timer and kill-switch runtime, managed attempt execution, and presentation remain separate modules. It stores no task graph or scheduler history and starts providers only under a lease owned by the current scheduler session.
