# Identity and deployment

A role is a reusable contract, a hired agent is a durable named expert, and a provider executes one turn. An agent’s unique display name is identity metadata, not its role, authority, provider, or model. A platform participant speaks for the agent. A Discord bot is the agent’s one-to-one external principal for one deployment binding. Naming, channel membership, employment, provider choice, and execution authority are separate state transitions.

The `@lervo/agent-organization` domain projection replays repository events for team binding, explicit team-kind revision, exact hired-agent membership and display-name revisions, external-principal deployments, channel membership, and deliberation participation. It owns lifecycle invariants independently of Discord, provider adapters, CLI parsing, and storage. The CLI owns explicit binding, reclassification, and identity synchronization. The Node composition boundary hashes native Discord coordinates and validates runtime identity before opening ingress. These boundaries separate domain policy, mutation coordination, configuration parsing, and external integration.

Raw external IDs and credentials never enter organization history. Stable hashes bind deployments; owner-only Node configuration retains native Discord coordinates. An organization-bound runtime fails closed if any repository, team, agent, role, provider-policy, bot, configuration, or channel coordinate differs. Standalone local operation remains available when no organization binding is configured.

Changing execution configuration is an explicit deployment rotation: active channel memberships end, the old deployment is retired, and one immutable deployment plus its channel memberships are bound in one repository mutation. The hired agent, display name, role membership, and reviewed context remain unchanged. Exact repeated binding is a no-op. An external principal cannot be rotated away from another active agent.

Managed conversation runs carry the durable speaking agent ID as root work causality. Provider and model remain turn-execution evidence. A shared role or identical message therefore cannot collapse two agents’ response ownership.
