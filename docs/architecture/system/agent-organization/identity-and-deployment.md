# Identity and deployment

A role is a reusable contract; a hired agent is a durable named expert; a provider executes one turn. The agent's unique display name is identity metadata, not its role, authority, provider, or model. A platform participant speaks for the agent. A Discord bot is the agent's one-to-one external principal for one deployment binding. Naming, channel membership, employment, provider choice, and execution authority are separate state transitions.

The `@lervo/agent-organization` domain projection replays repository events for team binding, explicit team-kind revision, exact hired-agent membership and display-name revisions, external-principal deployments, channel membership, and deliberation participation. It owns lifecycle invariants without depending on Discord, provider adapters, CLI parsing, or storage. The CLI owns explicit binding, reclassification, and identity synchronization. The Node composition boundary hashes native Discord coordinates and validates the resulting runtime identity before opening ingress. These boundaries separate domain policy, mutation coordination, configuration parsing, and external integration.

Raw external IDs and credentials never enter organization history. Stable hashes bind the deployment; owner-only Node configuration retains native Discord coordinates. An organization-bound runtime fails closed if any repository, team, agent, role, provider-policy, bot, configuration, or channel coordinate differs. Standalone local operation remains available when no organization binding is configured.

Managed conversation runs carry the durable speaking agent ID as root work causality. Provider and model remain turn execution evidence. A shared role or identical message therefore cannot collapse two agents' response ownership.
