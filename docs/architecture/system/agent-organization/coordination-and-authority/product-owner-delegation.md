# Product-owner delegation

## Scope

The central executive may delegate a repository product owner to one exact team. That owner may request `agent.hire` and `assignment.delegate` only for that team, within the bound role, budget, automation-depth, responsibility-path, and capability-ancestry constraints.

A hire creates a child workforce identity with no external speaker deployment. Organization-wide policy changes, other teams, Discord application creation, token issuance, and guild installation remain outside project-owner authority.

## Managed hiring effect

The installed managed-conversation effect `workforce_agent_hire` accepts only an exact `name`, installed `roleId`, and provider choice of `codex`, `claude`, or `any`. Runtime configuration requires the responding product owner's hired-agent and organization binding. Execution fixes the parent to that product owner and responsibility to the current repository.

The workforce store enforces role resolution, unique explicit naming, maximum delegation depth, repository capacity, and capability-package ancestry.

Human owners and separately admitted agent effect requesters may trigger the effect; ordinary conversation and shared-channel membership cannot.
