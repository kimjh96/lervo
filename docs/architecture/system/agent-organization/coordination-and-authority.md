# Coordination and authority

The multi-team operating report is a read-only composition of repository-owned projections. The executive policy evaluator is a pure decision boundary: it checks the named agent's appointment to executive responsibility, action and team allowlists, automation depth, budget observation, report integrity, and approval. It never performs an effect.

An installed organization-executive coordinator binds an allowed decision to one exact effect and a durable replay coordinate. Discord channel and thread creation use the Discord administration adapter; future Lervo UI actions can use another adapter without changing organization policy. Verified completion records a receipt; explicit rejection terminates; uncertain delivery never auto-retries.

Ordinary agent conversation remains read-only unless an existing authority path creates or changes an assignment, workstream, approval, or external effect. Bounded discussions reuse Lervo deliberation for evidence, disagreement, decision rules, and termination. Discord supplies distinct visible speakers.

## Product-owner delegation

The central executive may delegate a repository product owner to one exact team. That owner may request `agent.hire` and `assignment.delegate` only for that team, within the bound role, budget, automation-depth, responsibility-path, and capability-ancestry constraints. A hire creates a child workforce identity with no external speaker deployment. Organization-wide policy changes, other teams, Discord application creation, token issuance, and guild installation remain outside project-owner authority.

The installed managed-conversation effect `workforce_agent_hire` accepts only an exact `name`, installed `roleId`, and provider choice of `codex`, `claude`, or `any`. Runtime configuration requires the responding product owner's hired-agent and organization binding. Execution fixes the parent to that product owner and responsibility to the current repository. The workforce store enforces role resolution, unique explicit naming, maximum delegation depth, repository capacity, and capability-package ancestry.

Human owners and separately admitted agent effect requesters may trigger the effect; ordinary conversation and shared-channel membership cannot.
