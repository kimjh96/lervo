# Managed admission and activation

Before effects, the provider grounds requests into validated typed decisions. Orchestration resolves role, policy, skills, capabilities, context, write authorization, and verification. Adapters normalize native telemetry.

Activation is confirmed once, after E3 and before the write bridge or task turn. Failure closes the session without an activation-success event.

Managed runs require a verified workstream delivered with E1–E3. After reader-first writer activation, each managed admission records one provider-neutral causal event before `run.requested`. Version-1 writers and invalid ancestry block provider startup.

Deliberation uses one control root and explicit child relationships. Work IDs aggregate evidence but grant no objective, assignment, or completion authority.
