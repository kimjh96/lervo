# 0.1.0 trace bounded-default migration

Starting with Lervo 0.1.0, `lervo trace [last|run-id]` without mode options returns the first page of at most 50 events instead of a complete run report. This bounds memory and output size for long runs.

## Requesting a complete report

Automation that uses `status`, `firstOccurredAt`, `lastOccurredAt`, `sessionIds`, or the complete `events` list must request `--full` explicitly:

```sh
lervo trace last --full --json
lervo trace <run-id> --full --json
```

The result remains `TraceReport` v1. The existing maximum of 1,000 events per run still applies. A larger run fails with `trace_result_too_large`; Lervo does not return a partial result as though it were complete.

## Using bounded pages

The default JSON is `TracePageReport` v1. It does not contain whole-run aggregates such as `status`. Use `page.hasMore` and `page.nextCursor` to continue:

```sh
lervo trace last --json
lervo trace --cursor <next-cursor> --json
```

Set a fixed page size with `--page-size <1..100>`. A cursor is bound to the event snapshot observed by the first request. If source events change, the next request fails with `trace_cursor_stale`; restart from the first page.

## Detecting the mode in automation

Do not parse human help or historical stderr warnings. Read the machine report:

```sh
lervo trace --capabilities
```

The 0.1.0 report returns `defaultMode=page`, `explicit=false` for page mode, and an empty `deprecations` list. Consumers that need a complete report should always pass `--full`, regardless of the current default. Validate `TraceCapabilitiesReport`, `TracePageReport`, and `TraceReport` with their respective v1 readers.

This migration changes only the report selected by an option-free CLI call. It does not change the event schema, project sources, or the existing complete trace report schema.
