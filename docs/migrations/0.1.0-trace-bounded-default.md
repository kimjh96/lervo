# 0.1.0 trace 기본 출력 migration

Lervo 0.1.0부터 옵션 없는 `lervo trace [last|run-id]`는 전체 실행 보고서가 아니라 최대 50개 event의 첫 페이지를 반환합니다. 긴 실행에서도 기본 명령의 메모리와 출력 크기를 제한하기 위한 변경입니다.

## 전체 보고서가 필요한 경우

기존 자동화가 `status`, `firstOccurredAt`, `lastOccurredAt`, `sessionIds`와 전체 `events`를 사용한다면 `--full`을 명시합니다.

```sh
lervo trace last --full --json
lervo trace <run-id> --full --json
```

결과는 기존 `TraceReport` v1이며 run당 최대 1,000개 event 제한은 그대로입니다. 1,000개를 넘으면 일부를 전체처럼 반환하지 않고 `trace_result_too_large`로 실패합니다.

## 제한된 페이지를 사용하는 경우

기본 JSON은 `TracePageReport` v1입니다. `status` 같은 전체 실행 집계는 없으며 `page.hasMore`와 `page.nextCursor`로 다음 페이지 존재를 확인합니다.

```sh
lervo trace last --json
lervo trace --cursor <next-cursor> --json
```

페이지 크기를 고정하려면 `--page-size <1..100>`을 사용합니다. Cursor는 처음 조회한 event snapshot에 묶이므로 원본이 추가되면 `trace_cursor_stale`로 실패하며 첫 페이지부터 다시 조회해야 합니다.

## 자동화에서 mode 확인

사람용 help나 과거 stderr 경고를 파싱하지 말고 다음 report를 읽습니다.

```sh
lervo trace --capabilities
```

0.1.0 report는 `defaultMode=page`, page mode의 `explicit=false`, 빈 `deprecations`를 반환합니다. 전체 보고서가 필요한 consumer는 기본값과 무관하게 항상 `--full`을 사용해야 합니다. `TraceCapabilitiesReport`, `TracePageReport`, `TraceReport`는 각각의 v1 reader로 검증합니다.

이 migration은 event schema, project 원본과 기존 trace report schema를 바꾸지 않습니다. 바뀌는 것은 옵션 없는 CLI 호출이 선택하는 report 종류뿐입니다.
