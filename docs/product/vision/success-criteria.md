# Product success criteria

1. A new repository can initialize, migrate knowledge, lint, query, and run locally.
2. An existing repository can migrate without losing user bytes or provider-specific semantics.
3. Codex and Claude pass the same adapter contracts.
4. A clean clone or another Lervo installation can reproduce tracked knowledge without a Hub.
5. Generated entrypoints and indexes remain bounded as the repository grows.
6. Every material change has a reviewable plan, verification result, and privacy-bounded event meaning.
7. An initialized repository can converge to an installed Lervo build without hand-composing subsystem migrations or confusing a semantic version with exact runtime bytes.
8. A supported conversation surface can show requested code, perform authorized repository work through the same managed Codex and Claude capabilities as local entrypoints, and return verified results without becoming an execution authority.
9. Installed comparisons demonstrate whether Lervo grounding, evidence, and verification improve exact task outcomes over direct provider baselines. Lervo never substitutes an unsupported universal quality claim for measured results. Measured hits and usage form the operating feedback loop and are reported on every turn.
10. One owner can operate central leadership plus the Shiflo, Plen, and Arac repository teams. Each hired agent retains isolated durable context and can collaborate through bounded conversations, threads, replies, mentions, assignments, and handoffs. The organization self-organizes: agents answer when relevant, address each other, and the product owner staffs missing roles within budget.
11. Every Lervo-owned product capability passes its core contract and a real installed Discord journey. A host-neutral conformance scenario proves that a future first-party surface can reuse it without Discord behavior or a second authority.
12. Repository grounding uses the resolved qualified search plan. Knowledge learned through any surface becomes canonical only through exact source-bound review and materialization.
13. Product-host, event, and observation evolution remains additive, migration-safe, rollback-aware, and interpretable across current and predecessor releases.
